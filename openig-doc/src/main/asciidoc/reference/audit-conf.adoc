== Audit Framework

ifdef::env-site[]
anchor:audit-conf[]
endif::env-site[]

OpenIG uses the Open Identity Platform common audit framework to log system boundary events using an implementation that is common across the ForgeRock platform.
[#AuditService]
=== AuditService — enable common audit service for a route

[#d210e10012]
==== Description
This object serves to configure the audit service for a route. The audit service uses the Open Identity Platform common audit event framework.

The route is decorated with an `auditService` field whose value references the configuration, either inline or from the heap.

[#d210e10027]
==== Usage

[source, javascript]
----
{
    "name": string,
    "type": "AuditService",
    "config": {
        "config": object,
        "event-handlers": array
    }
}
----

[#d210e10033]
==== Properties
--

The heap object's `config` object has the following properties:

`"config"`: __object, optional__::
Settings for the audit service. Omit the inner `config` object to use the defaults.
+
[open]
====
`"handlerForQueries"`: __string, optional__::
Name of the enabled event handler that handles audit service read and query requests.
Choose a handler that supports these operations.
By default, the audit service has no query handler.

`"availableAuditEventHandlers"`: __array of strings, optional__::
The service accepts this list of fully qualified class names.
OpenIG registers handlers using `event-handlers`.

`"filterPolicies"`: __object, optional__::
Controls which fields are removed before an audit event is sent to its handlers.
Both `field` and `value` are objects with the same behavior:
+
[open]
======
`"excludeIf"`: __array of strings, optional__::
JSON Pointers whose first segment is the audit topic and whose remaining segments identify the field.
For example, `/access/http/request/headers` removes the request headers from events on the `access` topic.
The event is still sent to the handlers.
The default is an empty list.

`"includeIf"`: __array of strings, optional__::
The service accepts this property without applying it.
======

====

`"event-handlers"`: __array of objects, optional__::
The handler definitions. The default is an empty array.
+
Each entry has a `class` with the handler's fully qualified Java class name and a `config` object with settings for that handler.
Each handler needs a `config.name` that is unique within the service.
Handlers are enabled by default. Set `topics` to `["access"]` to receive route audit events.
The default topic list is empty.
+
OpenIG ships the following event handlers:

* xref:#CsvAuditEventHandler[CsvAuditEventHandler(5)]
* xref:#JdbcAuditEventHandler[JdbcAuditEventHandler(5)]
* xref:#JmsAuditEventHandler[JmsAuditEventHandler(5)]
* xref:#JsonAuditEventHandler[JsonAuditEventHandler(5)]
* xref:#JsonStdoutAuditEventHandler[JsonStdoutAuditEventHandler(5)]
* xref:#SyslogAuditEventHandler[SyslogAuditEventHandler(5)]
* xref:#ElasticsearchAuditEventHandler[ElasticsearchAuditEventHandler(5)]

--

[#d210e10190]
==== Example
The following example configures an audit service to log access event messages in a comma-separated values file, named `/path/to/audit/logs/access.csv`:

[source, json]
----
{
    "name": "AuditService",
    "type": "AuditService",
    "config": {
        "event-handlers": [
            {
                "class": "org.forgerock.audit.handlers.csv.CsvAuditEventHandler",
                "config": {
                    "name": "csv",
                    "logDirectory": "/path/to/audit/logs",
                    "topics": [
                        "access"
                    ]
                }
            }
        ]
    }
}
----
The following example route uses the audit service:

[source, json]
----
{
    "handler": "ClientHandler",
    "auditService": "AuditService"
}
----

[#CsvAuditEventHandler]
=== CsvAuditEventHandler — log audit events to CSV files

[#d210e10226]
==== Description
An audit event handler that responds to events by logging messages to files in comma-separated values (CSV) format.

The configuration is declared in an audit service configuration. For details, see xref:#AuditService[AuditService(5)].

[#d210e10240]
==== Usage

[source, javascript]
----
{
    "class": "org.forgerock.audit.handlers.csv.CsvAuditEventHandler",
    "config": {
        "name": string,
        "logDirectory": string,
        "topics": array,
        "enabled": boolean,
        "formatting": {
            "quoteChar": single-character string,
            "delimiterChar": single-character string,
            "endOfLineSymbols": string
        },
        "buffering": {
            "enabled": boolean,
            "autoFlush": boolean
        },
        "security": {
            "enabled": boolean,
            "filename": string,
            "password": string,
            "signatureInterval": duration,
            "keyStoreHandlerName": string
        },
        "fileRetention": {
            "maxDiskSpaceToUse": number,
            "maxNumberOfHistoryFiles": number,
            "minFreeSpaceRequired": number
        },
        "fileRotation": {
            "rotationEnabled": boolean,
            "maxFileSize": number,
            "rotationFilePrefix": string,
            "rotationFileSuffix": string,
            "rotationInterval": duration,
            "rotationTimes": array
        },
        "rotationRetentionCheckInterval": duration
    }
}
----
The values in this configuration object can use expressions as long as they resolve to the correct types for each field. For details about expressions, see xref:expressions-conf.adoc#Expressions[Expressions(5)].

[#d210e10249]
==== Configuration
--
The `"config"` object has the following properties:

`"name"`: __string, required__::
The name of the event handler.

`"logDirectory"`: __string, required__::
The file system directory where log files are written.

`"topics"`: __array of strings, optional__::
The audit topics this handler receives. Set this to `["access"]` for OpenIG route audit events.
Default: `[]`.

`"enabled"`: __boolean, optional__::
Whether this event handler is active.

+
Default: true.

`"formatting"`: __object, optional__::
Formatting settings for CSV log files.
+
[open]
====
The formatting object has the following fields:

`"quoteChar"`: __single-character string, optional__::
The character used to quote CSV entries.

+
Default: `"`.

`"delimiterChar"`: __single-character string, optional__::
The character used to delimit CSV entries.

+
Default: `,`.

`"endOfLineSymbols"`: __string, optional__::
The character or characters that separate a line.

+
Default: system-dependent line separator defined for the JVM.

====

`"buffering"`: __object, optional__::
Settings for buffering writes to CSV log files. The configuration also accepts `bufferingConfiguration` as the object name.
+
[open]
====
The buffering object has the following fields:

`"enabled"`: __boolean, optional__::
Whether log buffering is enabled.

+
Default: false.

`"autoFlush"`: __boolean, optional__::
When buffering is enabled, controls whether each event is flushed after writing.

+
Default: true.

====

`"security"`: __object, optional__::
Security settings for CSV log files. These settings govern tamper-evident logging, whereby messages are signed. By default tamper-evident logging is not enabled.
+
[open]
====
The security object has the following fields:

`"enabled"`: __boolean, optional__::
Whether tamper-evident logging is enabled.

+
Default: false.

+
Tamper-evident logging requires `filename`, `password`, and `signatureInterval`. For details, see xref:#log-common-audit-keystore["Preparing a Keystore for Tamper-Evident Logs"].

`"filename"`: __string, required when signing is enabled__::
File system path to the keystore containing the private key for tamper-evident logging.

+
The keystore must be a keystore of type `JCEKS`. For details, see xref:#log-common-audit-keystore["Preparing a Keystore for Tamper-Evident Logs"].

`"password"`: __string, required when signing is enabled__::
The password for the keystore for tamper-evident logging.

+
This password is used for the keystore and for private keys. For details, see xref:#log-common-audit-keystore["Preparing a Keystore for Tamper-Evident Logs"].

`"signatureInterval"`: __duration, required when signing is enabled__::
The time interval after which to insert a signature in the CSV file.
Use a positive, finite duration.
+
include::../partials/sec-duration-description.adoc[]

`"keyStoreHandlerName"`: __string, optional__::
Commons accepts this property, which requires a `KeyStoreHandlerProvider`.
OpenIG's audit service does not supply that provider. Use the JCEKS file settings to enable signing.

====

[#audit-file-retention]
`"fileRetention"`: __object, optional__::
File retention settings for audit log files. The CSV handler applies these settings when file rotation is enabled.
+
[open]
====
The file retention object has the following fields:

`"maxDiskSpaceToUse"`: __number, optional__::
The maximum disk space in bytes the audit logs can occupy. A setting of 0 or less indicates that the policy is disabled.

+
Default: `-1`.

`"maxNumberOfHistoryFiles"`: __number, optional__::
The maximum number of historical log files to retain. A setting of 0 or less disables the file count limit.

+
Default: `-1`.

`"minFreeSpaceRequired"`: __number, optional__::
The minimum free space in bytes that the system must contain for logs to be written. A setting of 0 or less indicates that the policy is disabled.

+
Default: `-1`.

====

[#audit-file-rotation]
`"fileRotation"`: __object, optional__::
File rotation settings for audit log files.
+
[open]
====
The file rotation object has the following fields:

`"rotationEnabled"`: __boolean, optional__::
Whether file rotation is enabled. Set this to `true` to apply the configured rotation policies.

+
Default: false.

`"maxFileSize"`: __number, optional__::
The maximum file size of an audit log file in bytes. A setting of 0 or less indicates that the policy is disabled.

+
Default: `-1`.

`"rotationFilePrefix"`: __string, optional__::
The prefix for rotated log files. By default, the active log file's name is used.

`"rotationFileSuffix"`: __string, optional__::
The suffix for rotated log files. Use a Joda-Time `DateTimeFormat` timestamp pattern, optionally followed by `.gz` to compress the rotated file.

+
Default: `-yyyy.MM.dd-HH.mm.ss.gz`.

`"rotationInterval"`: __duration, optional__::
The time interval after which to rotate log files when rotation is enabled.
Use a positive, finite duration.
The default, `disabled`, leaves interval-based rotation off.
+
include::../partials/sec-duration-description.adoc[]


`"rotationTimes"`: __array of durations, optional__::
The times at which to rotate files each day when rotation is enabled, expressed as durations after midnight.
Default: `[]`.

+
The following example schedules rotation six and twelve hours after midnight:
+

[source, text]
----
"rotationTimes": [ "6 hours", "12 hours" ]
----
+
include::../partials/sec-duration-description.adoc[]


====

`"rotationRetentionCheckInterval"`: __duration, optional__::
The interval between checks of rotation and retention policies. When these policies are enabled, use a finite duration of at least 1 millisecond.
+
Default: 5 seconds.
+
include::../partials/sec-duration-description.adoc[]

[#log-common-audit-keystore]
==== Preparing a Keystore for Tamper-Evident Logs
Tamper-evident logging depends on a public key/private key pair and on a secret key that are stored together in a JCEKS keystore. Follow these steps to prepare the keystore:

====

. Generate a key pair in the keystore.
+
The CSV event handler expects a JCEKS-type keystore with a key alias of `Signature` for the signing key, where the key is generated with the `RSA` key algorithm and the `SHA256withRSA` signature algorithm:
+

[source, console]
----
$ keytool \
 -genkeypair \
 -keyalg RSA \
 -sigalg SHA256withRSA \
 -alias "Signature" \
 -dname "CN=openig.example.com,O=Example Corp,C=FR" \
 -keystore /path/to/audit-keystore \
 -storetype JCEKS \
 -storepass password \
 -keypass password
----

. Generate a secret key in the keystore.
+
The CSV event handler expects a JCEKS-type keystore with a key alias of `Password` for the symmetric key, where the key is generated with the `HmacSHA256` key algorithm and 256-bit key size:
+

[source, console]
----
$ keytool \
 -genseckey \
 -keyalg HmacSHA256 \
 -keysize 256 \
 -alias "Password" \
 -keystore /path/to/audit-keystore \
 -storetype JCEKS \
 -storepass password \
 -keypass password
----

. Verify the content of the keystore:
+

[source, console]
----
$ keytool \
 -list \
 -keystore /path/to/audit-keystore \
 -storetype JCEKS \
 -storepass password

Keystore type: JCEKS
Keystore provider: SunJCE

Your keystore contains 2 entries

signature, Nov 27, 2015, PrivateKeyEntry,
Certificate fingerprint (SHA1): 4D:CF:CC:29:...:8B:6E:68:D1
password, Nov 27, 2015, SecretKeyEntry,
----

====

[#d210e11329]
==== Example
For instructions on recording audit events in a CSV file, see xref:../gateway-guide/chap-auditing.adoc#audit-csv[ To Record Audit Events In a CSV File ] in the __Gateway Guide__.

This event handler writes to `/path/to/audit/logs/tamper-evident-access.csv` with a 10-second signature interval. Set `filename` and `password` to match the prepared JCEKS keystore.

[source, json]
----
{
    "class": "org.forgerock.audit.handlers.csv.CsvAuditEventHandler",
    "config": {
        "name": "csv",
        "topics": ["access"],
        "logDirectory": "/path/to/audit/logs",
        "security": {
            "enabled": true,
            "filename": "/path/to/audit-keystore",
            "password": "password",
            "signatureInterval": "10 seconds"
        }
    }
}
----

[#d210e11344]
==== Javadoc
link:{apidocs-url}/org/forgerock/audit/handlers/csv/CsvAuditEventHandler.html[org.forgerock.audit.handlers.csv.CsvAuditEventHandler, window=\_blank]

[#JdbcAuditEventHandler]
=== JdbcAuditEventHandler — log audit events to relational database

[#d210e11364]
==== Description
An audit event handler that writes events to a relational database table.

Install HikariCP and the database's JDBC driver on the servlet container's classpath so that the OpenIG application can load them.
The OpenIG WAR includes the audit handler. HikariCP and the JDBC driver must be supplied by the deployment.

The configuration is declared in an audit service configuration. For details, see xref:#AuditService[AuditService(5)].

[#d210e11378]
==== Usage

[source, javascript]
----
{
    "class": "org.forgerock.audit.handlers.jdbc.JdbcAuditEventHandler",
    "config": {
        "name": string,
        "topics": array,
        "databaseType": string,
        "enabled": boolean,
        "buffering": {
            "enabled": boolean,
            "writeInterval": duration,
            "autoFlush": boolean,
            "maxBatchedEvents": number,
            "maxSize": number,
            "writerThreads": number
        },
        "connectionPool": {
            "dataSourceClassName": string,
            "driverClassName": string,
            "jdbcUrl": string,
            "username": string,
            "password": string,
            "autoCommit": boolean,
            "connectionTimeout": number,
            "idleTimeout": number,
            "maxLifetime": number,
            "minIdle": number,
            "maxPoolSize": number,
            "poolName": string
        },
        "tableMappings": [
            {
                "event": string,
                "table": string,
                "fieldToColumn": {
                    "event-field": "database-column"
                }
            }
        ]
    }
}
----
The values in this configuration object can use expressions as long as they resolve to the correct types for each field. For details about expressions, see xref:expressions-conf.adoc#Expressions[Expressions(5)].

[#d210e11387]
==== Configuration
--
The `"config"` object has the following properties:

`"name"`: __string, required__::
The name of the event handler.

`"topics"`: __array of strings, optional__::
The audit topics this handler receives. Set this to `["access"]` for OpenIG route audit events.
Default: `[]`.

`"databaseType"`: __string, required__::
The database type name.

+
Built-in support is provided for `oracle`, `mysql`, and `h2`. Unrecognized database types rely on a link:{apidocs-url}/org/forgerock/audit/handlers/jdbc/providers/GenericDatabaseStatementProvider.html[GenericDatabaseStatementProvider, window=\_top].

`"enabled"`: __boolean, optional__::
Whether this event handler is active.

+
Default: true.

`"buffering"`: __object, optional__::
Settings for buffering database writes. The configuration also accepts `bufferingConfiguration` as the object name.
+
[open]
====
The buffering object has the following fields:

`"enabled"`: __boolean, optional__::
Whether audit events are buffered before writing to the database. With buffering disabled, each event is written directly.

+
Default: false.

`"writeInterval"`: __string, optional__::
The configuration accepts this property with a default of `disabled`.
With buffering enabled the writer polls an empty queue every 10 milliseconds regardless of this setting.


`"autoFlush"`: __boolean, optional__::
Whether to drain the event queue at shutdown when buffering is enabled.

+
Default: true.

`"maxBatchedEvents"`: __number, optional__::
The maximum number of event messages batched into a link:https://docs.oracle.com/en/java/javase/11/docs/api/java.sql/java/sql/PreparedStatement.html[PreparedStatement, window=\_blank].

+
Default: 100.

`"maxSize"`: __number, optional__::
The maximum size of the queue of buffered event messages.

+
Default: 5000.

`"writerThreads"`: __number, optional__::
The number of threads to write buffered event messages to the database.

+
Default: 1.

====

`"connectionPool"`: __object, required__::
Connection pool settings for sending messages to the database.
+
[open]
====
The connection pool object has the following fields:

`"dataSourceClassName"`: __string, optional__::
The fully qualified class name of the data source. Configure either a data source or a JDBC URL.

`"driverClassName"`: __string, optional__::
The fully qualified class name of the JDBC driver. Set it if HikariCP cannot discover the driver from the JDBC URL.

`"jdbcUrl"`: __string, required for URL-based connections__::
The JDBC URL for the database.

`"username"`: __string, optional__::
The username to use when the connection requires authentication. The account must have access to write audit events.

`"password"`: __string, optional__::
The password to use when the connection requires authentication.

`"autoCommit"`: __boolean, optional__::
Whether to commit transactions automatically when writing messages.

+
Default: true.

`"connectionTimeout"`: __number, optional__::
The number of milliseconds to wait for a connection from the pool before timing out.

+
Default: 30000.

`"idleTimeout"`: __number, optional__::
The number of milliseconds to allow a database connection to remain idle before timing out.

+
Default: 600000.

`"maxLifetime"`: __number, optional__::
The number of milliseconds to allow a database connection to remain in the pool.

+
Default: 1800000.

`"minIdle"`: __number, optional__::
The minimum number of idle connections in the pool.

+
Default: 10.

`"maxPoolSize"`: __number, optional__::
The maximum number of connections in the pool.

+
Default: 10.

`"poolName"`: __string, optional__::
The name of the connection pool.

====

`"tableMappings"`: __array of objects, required__::
Table mappings for directing event content to database table columns.
+
[open]
====
A table mappings object has the following fields:

`"event"`: __string, required__::
The audit event that the table mapping is for.

+
Set this to `access`.

`"table"`: __string, required__::
The name of the database table that corresponds to the mapping.

`"fieldToColumn"`: __object, required__::
This object maps the names of audit event fields to database columns, where the keys and values are both strings.

+
Audit event fields use JSON pointer notation, and are taken from the JSON schema for the audit event content.

====

--

[#d210e11889]

{
    "class": "org.forgerock.audit.handlers.jdbc.JdbcAuditEventHandler",

                    "client/port": "client_port",
                    "request/protocol": "request_protocol",
                    "request/operation": "request_operation",
                    "request/detail": "request_detail",
                    "http/request/secure": "http_request_secure",
                    "http/request/method": "http_request_method",
                    "http/request/path": "http_request_path",
                    "http/request/queryParameters": "http_request_queryparameters",
                    "http/request/headers": "http_request_headers",
                    "http/request/cookies": "http_request_cookies",
                    "http/response/headers": "http_response_headers",
                    "response/status": "response_status",
                    "response/statusCode": "response_statuscode",

[#JmsAuditEventHandler]
=== JmsAuditEventHandler — publish audit events to a JMS topic

==== Description

The handler sends a JMS text message containing a JSON object with the fields `auditTopic` and `event`.
Configure it in xref:#AuditService[AuditService(5)].

Make a Jakarta JMS provider and its JNDI implementation available to OpenIG in the servlet container.
The OpenIG WAR includes the Jakarta JMS API.
Configure JNDI bindings for a Jakarta JMS `ConnectionFactory` and `Topic` and ensure OpenIG can publish to the topic.

==== Configuration

The handler's `class` is `org.forgerock.audit.handlers.jms.JmsAuditEventHandler`.
Its `config` object accepts these properties:

`"name"`: __string, required__::
A unique handler name within the audit service.

`"topics"`: __array of strings, optional__::
The audit topics this handler receives. Set this to `["access"]` for OpenIG route audit events.
Default: `[]`.

`"enabled"`: __boolean, optional__::
Whether this event handler is active.
Default: `true`.

`"deliveryMode"`: __string, required__::
The JMS delivery mode. Use `PERSISTENT` or `NON_PERSISTENT`.

`"sessionMode"`: __string, required__::
The JMS session acknowledgement mode. Use `AUTO`, `CLIENT`, or `DUPS_OK`.

`"jndi"`: __object, optional__::
The JNDI environment and lookup names used to obtain the connection factory and destination.
+
[open]
====
`"contextProperties"`: __object, optional__::
String properties passed to the JNDI initial context, such as `java.naming.factory.initial` and `java.naming.provider.url`.
The required properties depend on the provider and the container.
Default: `{}`.

`"topicName"`: __string, optional__::
The JNDI name of the JMS topic to publish messages to.
The configuration also accepts `jmsTopicName`.
Default: `audit`.

`"connectionFactoryName"`: __string, optional__::
The JNDI name of the Jakarta JMS connection factory.
The configuration also accepts `jmsConnectionFactoryName`.
Default: `connectionFactory`.
====

`"batch"`: __object, optional__::
Settings for queued publication.
+
[open]
====
`"batchEnabled"`: __boolean, optional__::
Whether to publish queued events in batches. The default, `false`, publishes each event directly.

`"capacity"`: __integer, optional__::
The maximum number of events that can be queued. Use a value greater than zero.
Default: `1`.

`"threadCount"`: __integer, optional__::
The number of worker threads publishing events. Use a value greater than zero.
Default: `1`.

`"maxBatchedEvents"`: __integer, optional__::
The maximum number of events to take from the queue per batch. Use a value greater than zero.
Default: `1`.

`"insertTimeoutSec"`: __integer, optional__::
Seconds to wait for space in the queue when it is full.
Default: `60`.

`"shutdownTimeoutSec"`: __integer, optional__::
Seconds to wait for publishing workers to finish during shutdown.
Default: `60`.

`"pollTimeoutSec"`: __integer, optional__::
The configuration accepts this property with a default of `10`.
The publisher polls the queue every 10 milliseconds regardless of this setting.
====

==== Example

This handler uses the default JNDI environment. Bind the connection factory as `connectionFactory` and the JMS topic as `audit` in that environment, or configure the lookup names for your provider.

[source, json]
----
{
    "class": "org.forgerock.audit.handlers.jms.JmsAuditEventHandler",
    "config": {
        "name": "jms",
        "topics": ["access"],
        "deliveryMode": "PERSISTENT",
        "sessionMode": "AUTO",
        "jndi": {
            "topicName": "audit",
            "connectionFactoryName": "connectionFactory"
        }
    }
}

=== SyslogAuditEventHandler — log audit events to the system log

[#d210e11930]
==== Description
An audit event handler that responds to events by logging messages to the UNIX system log as governed by RFC 5424, link:https://tools.ietf.org/html/rfc5424[The Syslog Protocol, window=\_blank].

The configuration is declared in an audit service configuration. For details, see xref:#AuditService[AuditService(5)].

[#d210e11948]
==== Usage

[source, javascript]
----
{
    "class": "org.forgerock.audit.handlers.syslog.SyslogAuditEventHandler",
    "config": {
        "name": string,
        "topics": array,
        "enabled": boolean,
        "protocol": string,
        "host": string,
        "port": number,
        "connectTimeout": number,
        "facility": string,
        "buffering": {
            "enabled": boolean
        },
        "severityFieldMappings": [
            {
                "topic": string,
                "field": string,
                "valueMappings": {
                    "field-value": "syslog-severity"
                }
            }
        ]
    }
}
----
The values in this configuration object can use expressions as long as they resolve to the correct types for each field. For details about expressions, see xref:expressions-conf.adoc#Expressions[Expressions(5)].

[#d210e11958]
==== Configuration
--
The `"config"` object has the following properties:

`"name"`: __string, required__::
The name of the event handler.

`"topics"`: __array of strings, optional__::
The audit topics this handler receives. Set this to `["access"]` for OpenIG route audit events.
Default: `[]`.

`"enabled"`: __boolean, optional__::
Whether this event handler is active.
Default: `true`.

`"protocol"`: __string, required__::
The transport protocol used to send event messages to the Syslog daemon.

+
Set this to `TCP` or `UDP`. The TCP connection uses plain TCP.

`"host"`: __string, required__::
The hostname or IP address of the Syslog daemon. Use the host without a URL scheme.

`"port"`: __number, required__::
The port of the Syslog daemon to which to send event messages.

+
The value must be between 0 and 65535.

`"connectTimeout"`: __number, required for TCP__::
The TCP connection timeout in milliseconds. Use a positive value.
UDP ignores this setting.

`"facility"`: __string, required__::
The Syslog facility to use for event messages.
+
[open]
====
Set this to one of the following values:

`KERN`::
Kernel messages

`USER`::
User-level messages

`MAIL`::
Mail system

`DAEMON`::
System daemons

`AUTH`::
Security/authorization messages

`SYSLOG`::
Messages generated internally by `syslogd`

`LPR`::
Line printer subsystem

`NEWS`::
Network news subsystem

`UUCP`::
UUCP subsystem

`CRON`::
Clock daemon

`AUTHPRIV`::
Security/authorization messages

`FTP`::
FTP daemon

`NTP`::
NTP subsystem

`LOGAUDIT`::
Log audit

`LOGALERT`::
Log alert

`CLOCKD`::
Clock daemon

`LOCAL0`::
Local use 0

`LOCAL1`::
Local use 1

`LOCAL2`::
Local use 2

`LOCAL3`::
Local use 3

`LOCAL4`::
Local use 4

`LOCAL5`::
Local use 5

`LOCAL6`::
Local use 6

`LOCAL7`::
Local use 7

Settings for buffering messages before writing them to Syslog.
The configuration also accepts `bufferingConfiguration` as the object name.
+
[open]
====
`"enabled"`: __boolean, optional__::
Whether to send messages through an asynchronous queue.
Default: `false` (send each message directly).
When buffering is enabled, the queue holds up to 5,000 messages. The handler accepts only `enabled` in this object.

====

`"severityFieldMappings"`: __array of objects, optional__::
Selects which audit event field supplies the Syslog severity for each topic.

It falls back to `INFORMATIONAL` when there is no mapping, no field value, or an unrecognized value.

[open]

`"topic"`: __string, required__::

[open]

`EMERGENCY`::
System is unusable.

`ALERT`::
Action must be taken immediately.

`CRITICAL`::
Critical conditions.

`ERROR`::
Error conditions.

`WARNING`::
Warning conditions.

`NOTICE`::
Normal but significant condition.

Informational messages.

`DEBUG`::

[#ElasticsearchAuditEventHandler]
=== ElasticsearchAuditEventHandler — log audit events in the Elasticsearch search and analytics engine

[#d210e12408]
==== Description
An audit event handler that writes to the Elasticsearch search and analytics engine. The handler uses the document API for individual events and the Bulk API when buffering is enabled.

The configuration is declared in an audit service configuration. For information, see xref:#AuditService[AuditService(5)].

For Elasticsearch downloads and installation instructions, see the Elasticsearch link:https://www.elastic.co/guide/en/elasticsearch/reference/current/getting-started.html[Getting Started, window=\_blank] document.

A special client handler called `ElasticsearchClientHandler` can be defined to send audit events to Elasticsearch. You can use this client handler to capture the exchange between the audit service and Elasticsearch, or to wrap the search with a filter, for example, the `OAuth2ClientFilter`.

To define an `ElasticsearchClientHandler`, create the following object in the heap for the Elasticsearch audit event handler

[source, json]
----
{
  "name": "ElasticsearchClientHandler",
  "type": "ClientHandler",
  "config": {}
}
----

[#d210e12445]
==== Usage

[source, javascript]
----
{
  "class": "org.forgerock.audit.handlers.elasticsearch.ElasticsearchAuditEventHandler",
  "config": {
    "name": string,
    "enabled": boolean,
    "connection" : {
      "host" : string,
      "port" : number,
      "useSSL" : boolean,
      "username" : string,
      "password" : string
    },
    "indexMapping" : {
      "indexName" : string
    },
    "buffering" : {
      "enabled" : boolean,
      "writeInterval" : duration,
      "maxSize" : number,
      "maxBatchedEvents" : number
    },
    "topics" : [ string, ... ]
  }
}
----
The values in this configuration object can use expressions if they resolve to the correct types for each field. For information about expressions, see xref:expressions-conf.adoc#Expressions[Expressions(5)].

[#d210e12455]

Default: `9200`
