== Getting Started

ifdef::env-site[]
anchor:chap-quickstart[]
endif::env-site[]

Run OpenIG on Jetty and proxy requests to a sample application. For Tomcat and other deployment options, see xref:chap-install.adoc#chap-install[Installation in Detail].

[#before-you-quickstart]
=== Before You Begin

Use JDK 17, 21, or 25 with Jetty 12. See xref:chap-install.adoc#configure-container[Configuring Deployment Containers] for the Java and container compatibility matrix. Keep ports 8080, 8081, and 8444 free for this tutorial.

[#quickstart-install]
=== Install OpenIG

. Download and extract link:https://jetty.org/download.html[Jetty 12]. Download the OpenIG WAR from the link:https://github.com/OpenIdentityPlatform/OpenIG/releases[OpenIG releases].
. Set `JETTY_HOME` to the extracted distribution. Create a separate `JETTY_BASE` for this instance and initialize it with the HTTP connector and Jakarta EE 9 web application modules.
+
[source, console]
----
$ export JETTY_HOME=/path/to/jetty-home
$ export JETTY_BASE="$HOME/jetty-openig"
$ mkdir -p "$JETTY_BASE"
$ cd "$JETTY_BASE"
$ java -jar "$JETTY_HOME/start.jar" --add-modules=http,ee9-deploy,ee9-annotations
----
+
The annotations module enables discovery of the servlet initializer that starts OpenIG.
. Copy the downloaded WAR to the Jetty deployment directory as `root.war`. Substitute the path to your download.
+
[source, console]
----
$ cp /path/to/downloaded/OpenIG.war "$JETTY_BASE/webapps/root.war"
----
. Start Jetty in the foreground from `JETTY_BASE`, with HTTP listening on the loopback interface for this tutorial.
+
[source, console]
----
$ cd "$JETTY_BASE"
$ java -jar "$JETTY_HOME/start.jar" jetty.http.host=127.0.0.1
----
. Verify that link:http://127.0.0.1:8080/[http://127.0.0.1:8080/] displays the OpenIG welcome page when you start with an empty OpenIG configuration directory. Stop Jetty with Ctrl+C before adding the configuration.

[#quickstart-sample-app]
=== Install an Application to Protect

Download the link:https://repo.maven.apache.org/maven2/org/openidentityplatform/openig/openig-doc/{openig-version}/openig-doc-{openig-version}-jar-with-dependencies.jar[sample HTTP server JAR] from Maven Central. From your download directory, run it in a separate terminal.

[source, console, subs="attributes"]
----
$ java -jar openig-doc-{openig-version}-jar-with-dependencies.jar
----

The sample server listens on port 8081 for HTTP and on port 8444 for HTTPS. You can pass two arguments to set different HTTP and HTTPS ports. If you change the HTTP port, use the same port in the OpenIG route and in the browser.

Visit link:http://127.0.0.1:8081/[http://127.0.0.1:8081/] and log in with username `demo` and password `changeit`. The application displays the username and information about your request. Use the sample server on a development machine with access restricted to the tutorial participants.

[#quickstart-configure]
=== Configure OpenIG

. Create the configuration and routes directories before starting OpenIG.
+
[source, console]
----
$ mkdir -p "$HOME/.openig/config/routes"
----
+
On Windows, create the equivalent directory `%APPDATA%\OpenIG\config\routes`. If you have set `OPENIG_BASE` or `openig.base`, use the `config` directory under that base instead.
. Save this complete configuration as `config/config.json` under the OpenIG base directory. It creates a `Router` and defines a named HTTP client for the routes.
+
[source#quickstart-config,json]
----
{
  "heap": [
    {
      "name": "ClientHandler",
      "type": "ClientHandler"
    }
  ],
  "handler": {
    "type": "Router"
  }
}
----
. Save this route as `config/routes/99-default.json` under the OpenIG base directory.
+
[source#quickstart-route,json]
----
{
  "baseURI": "http://127.0.0.1:8081",
  "handler": "ClientHandler"
}
----
+
The route has no condition, so it matches any request that reaches it. The `baseURI` decoration changes the scheme, host, and port to the sample application and preserves the request path and query string.
. Start Jetty again with the command from xref:#quickstart-install[Install OpenIG]. The default administrative mode is for evaluation. Before deploying outside this tutorial, configure xref:../reference/required-conf.adoc#admin-json[`admin.json`] for production.

[#quickstart-network-config]
=== Configure Hostnames for Other Tutorials

The local proxy example works with loopback addresses. Later tutorials use example hostnames to distinguish OpenIG from the protected application. When both run on your machine, add the following line to `/etc/hosts` on Unix-like systems or `%SystemRoot%\System32\drivers\etc\hosts` on Windows.

[source]
----
127.0.0.1    openig.example.com app.example.com
----

When the services run on separate hosts, resolve `openig.example.com` to the gateway address from the browser and `app.example.com` to the upstream address from OpenIG. See xref:chap-install.adoc#configure-network[Preparing the Network].

[#quickstart-try-it-out]
=== Try the Installation

Open link:http://127.0.0.1:8080/[http://127.0.0.1:8080/] in a browser. The OpenIG route forwards the request to the sample application, which returns its login page. If you configured the tutorial hostnames, you can use link:http://openig.example.com:8080/[http://openig.example.com:8080/] for the same test.

Next, add a route that logs in to the sample application with the demo credentials.

. Save the following route as `config/routes/01-static.json` under the OpenIG base directory.
+
[source, json]
----
{
  "condition": "${request.uri.path == '/static'}",
  "handler": {
    "type": "Chain",
    "config": {
      "filters": [
        {
          "type": "StaticRequestFilter",
          "config": {
            "method": "POST",
            "uri": "http://127.0.0.1:8081/",
            "form": {
              "username": ["demo"],
              "password": ["changeit"]
            }
          }
        }
      ],
      "handler": "ClientHandler"
    }
  }
}
----
. Wait for the Router to load the new route. Open link:http://127.0.0.1:8080/static[http://127.0.0.1:8080/static] and check that the response displays the username `demo`.

The Router checks `01-static.json` before `99-default.json`. When the request path is `/static`, the first route replaces the request with a login form POST and forwards it to the application. For more details on route matching and reloading, see xref:chap-routing.adoc#chap-routing[Configuring Routes]. To inspect request and response metadata while developing, see xref:chap-logging.adoc#chap-logging[Logging Events in OpenIG].
