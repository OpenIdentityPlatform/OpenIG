[#chap-logging]
== Logging Events in OpenIG

OpenIG uses SLF4J with Logback. Logback controls the logging level, message format, and destinations for OpenIG and for dependencies that log through SLF4J.

[#d2528e8353]
=== Default Logging Behaviour

The packaged configuration writes messages at `INFO` and higher to the console and to rolling files under the OpenIG base directory. Log events with a route ID go to `logs/route-<route-id>.log`. Log events without a route ID, including startup messages, go to `logs/route-system.log`. OpenIG makes the route ID available to Logback through SLF4J's mapped diagnostic context (MDC).

[#d2528e8428]
=== Configuring Logback

To change logging, create `config/logback.xml` under the OpenIG base directory and restart the container. For example, set the level of a specific logger in this file and retain `INFO` on the root logger. Logback supplies console, file, and rolling file appenders. A sifting appender can select a file using the `routeId` MDC key.

See xref:../reference/logging-conf.adoc#logging-conf[Logging Framework] and the link:https://logback.qos.ch/manual/configuration.html[Logback configuration manual].

[#chap-logging-example]
=== Separating Logs for Different Routes

[#d2528e8498]
.Enable HTTP message capture for a development route
====
. Prepare OpenIG as described in xref:chap-quickstart.adoc#chap-quickstart[Getting Started]. Save this route as `config/routes/40-logging.json` under the OpenIG base directory.
+
[source, json]
----
{
  "name": "40-logging",
  "condition": "${request.uri.path == '/logging'}",
  "handler": {
    "type": "StaticResponseHandler",
    "capture": ["request", "response"],
    "config": {
      "status": 200,
      "entity": "Check the 40-logging route log"
    }
  }
}
----
. Save the following logging configuration as `config/logback.xml` under the OpenIG base directory. The capture logger is set to `DEBUG`. The sifting appender writes each log message to a file according to its route ID.
+
[source, xml]
----
<configuration>
  <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
    <encoder>
      <pattern>%-5level %logger - %msg%n</pattern>
    </encoder>
  </appender>

  <appender name="BY_ROUTE" class="ch.qos.logback.classic.sift.SiftingAppender">
    <discriminator>
      <key>routeId</key>
      <defaultValue>system</defaultValue>
    </discriminator>
    <sift>
      <appender name="FILE-${routeId}" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>${openig.base}/logs/route-${routeId}.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
          <fileNamePattern>${openig.base}/logs/route-${routeId}-%d{yyyy-MM-dd}.%i.log</fileNamePattern>
          <maxFileSize>100MB</maxFileSize>
          <maxHistory>30</maxHistory>
          <totalSizeCap>3GB</totalSizeCap>
        </rollingPolicy>
        <encoder>
          <pattern>%d %-5level %logger - %msg%n</pattern>
        </encoder>
      </appender>
    </sift>
  </appender>

  <logger name="org.forgerock.openig.decoration.capture.CaptureDecorator" level="DEBUG"/>

  <root level="INFO">
    <appender-ref ref="CONSOLE"/>
    <appender-ref ref="BY_ROUTE"/>
  </root>
</configuration>
----
. Restart OpenIG. Visit link:http://127.0.0.1:8080/logging[http://127.0.0.1:8080/logging]. The file `logs/route-40-logging.log` should contain the request and response capture messages. Startup messages appear in `logs/route-system.log`.
====

Enable capture only while diagnosing a problem in a restricted environment. Captured headers can contain authorization credentials and session cookies, even with body capture disabled. See xref:../reference/decorators-conf.adoc#CaptureDecorator[CaptureDecorator(5)] for capture options.
