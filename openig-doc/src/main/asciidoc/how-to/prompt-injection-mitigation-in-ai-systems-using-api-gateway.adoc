== Prompt Injection Mitigation in AI Systems Using an API Gateway

[[prompt-injection-mitigation-in-ai-systems-using-api-gateway-introduction]]
=== Introduction

This local example puts OpenIG in front of an Ollama chat API. OpenIG checks the request, asks a local model to classify it and sanitizes returned text before sending it to the caller.

[[prompt-injection-mitigation-in-ai-systems-using-api-gateway-what-is-prompt-injection]]
=== What is prompt injection

A prompt injection tries to steer a model through untrusted content. See https://genai.owasp.org/llmrisk/llm01-prompt-injection/[the OWASP description]. The demo illustrates screening at the gateway using text-only, non-streaming requests. Applications must enforce access to their tools and data independently of the classifier.

[[prompt-injection-mitigation-in-ai-systems-using-api-gateway-preparing-the-environment]]
=== Prepare the environment

Save link:{how-to-downloads}/ollama/compose.yaml[compose.yaml] and link:{how-to-downloads}/ollama/prepare.sh[prepare.sh] in a new directory. The Compose stack publishes OpenIG on the local loopback interface and keeps Ollama on the internal network. The Ollama named volume stores the model across container replacement.

[source,bash]
----
sh prepare.sh
docker compose config --quiet
docker compose up -d --wait ollama
docker compose exec ollama ollama pull qwen2.5:0.5b
----

The preparation script creates `openig/config/routes/10-llm.json` and the base OpenIG configuration. Download the three filters below into `openig/scripts/groovy/`, then start OpenIG.

[source,bash]
----
docker compose up -d openig
----

The route matches POST requests to `/v1/chat/completions`. Its chain ends at `LlmDispatchHandler`, a `DispatchHandler` in the route heap. That handler sends the request to the Ollama container using a URI with no path component so the request path is preserved.

[[prompt-injection-mitigation-in-ai-systems-using-api-gateway-validation-and-cleaning-of-user-requests]]
==== Validate and clean requests

Save link:{how-to-downloads}/ollama/RequestGuardRail.groovy[RequestGuardRail.groovy]. This filter checks the requested model, limits the input length, replaces client-provided system messages and screens common suspicious input patterns. The allowed model is `qwen2.5:0.5b`.

[[prompt-injection-mitigation-in-ai-systems-using-api-gateway-using-a-third-party-llm-to-detect-prompt-injection]]
==== Classify the request

Save link:{how-to-downloads}/ollama/LlmGuardRail.groovy[LlmGuardRail.groovy]. The filter sends the request text to the local Ollama classifier. It forwards the request only when classification succeeds and every returned choice explicitly says `SAFE`. The filter closes the classifier response and its logs omit prompt and response content.

[[prompt-injection-mitigation-in-ai-systems-using-api-gateway-output-validation]]
==== Validate the output

Save link:{how-to-downloads}/ollama/ResponseGuardRail.groovy[ResponseGuardRail.groovy]. The sample removes fenced code and HTML-encodes the model's text for display in an HTML text node.

[[prompt-injection-mitigation-in-ai-systems-using-api-gateway-lets-check-the-solution]]
=== Test the route

Use an allowed model and a short message. The gateway returns a chat completion when the classifier accepts the request, or 403 when it declines or cannot classify it.

[source,bash]
----
curl -i http://localhost:8080/v1/chat/completions \
  -H 'Content-Type: application/json' \
  --data '{"model":"qwen2.5:0.5b","messages":[{"role":"user","content":"Hello"}]}'
----

Requesting a model outside the allowlist returns 403 before contacting Ollama.

[source,bash]
----
curl -i http://localhost:8080/v1/chat/completions \
  -H 'Content-Type: application/json' \
  --data '{"model":"other-model","messages":[{"role":"user","content":"Hello"}]}'
----

[[prompt-injection-mitigation-in-ai-systems-using-api-gateway-conclusion]]
=== Conclusion

The two checks can reject legitimate requests and miss malicious ones. Evaluate both failure modes on your application's traffic before applying the example.
