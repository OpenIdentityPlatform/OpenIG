== How to Protect a WebSocket Connection with OpenAM and OpenIG
:imagesdir: ../
include::../partials/how-to-downloads.adoc[]

[[how-to-protect-websocket-connection-with-openam-and-openig-introduction]]
=== Introduction

OpenIG checks the OpenAM session before allowing a browser to exchange WebSocket messages with an upstream service. In this demo, a browser connects to OpenIG on port 8081, OpenAM listens on port 8080, and the echo service is reachable only from the Compose network.

[[how-to-protect-websocket-connection-with-openam-and-openig-sample-websocket-service-introduction]]
=== Sample WebSocket service

Save link:{how-to-downloads}/websocket/compose.yaml[compose.yaml] and link:{how-to-downloads}/websocket/prepare.sh[prepare.sh] in the same empty directory. The example uses the https://hub.docker.com/r/jmalloc/echo-server[echo-server] image. Use a trusted upstream for this setup because OpenIG forwards the session cookie in the upstream WebSocket handshake.

Add the following entry to the hosts file on the machine running your browser.

[source,text]
----
127.0.0.1 openam.example.org openig.example.org
----

[[how-to-protect-websocket-connection-with-openam-and-openig-openig-configuration]]
=== OpenIG configuration

Generate the configuration and verify the Compose file.

[source,bash]
----
sh prepare.sh
docker compose config --quiet
----

The script creates the following files under `openig-config/`, mounted at `/var/openig/config` in the OpenIG container.

* `admin.json` and `config.json` configure the OpenIG router.
* `routes/10-ui.json` serves `static/ws-client.html` at `/ui`. The browser uses `ws:` on HTTP and `wss:` on HTTPS when connecting to `/ws-handler`.
* `routes/20-websocket.json` transforms the OpenAM session cookie using REST STS, returns 401 if no JWT is issued, and sends the JWT in the upstream `Authorization` header. The WebSocket client inside OpenIG supplies its own handshake key and protocol version.

The Compose file sets `openam` to the OpenAM deployment URL and `ws.secured` to `ws://echo-server:8080`. The upstream URL contains only the scheme, host and port so dispatch preserves the original request path. Use `wss:` for an upstream with TLS.

`org.openidentityplatform.openig.websocket.ttl` is the number of seconds for which OpenIG reuses a WebSocket authorization result. The default is 180 seconds. While the socket is open, the first message in either direction after that interval triggers another authorization check.

[[how-to-protect-websocket-connection-with-openam-and-openig-openam-configuration]]
=== OpenAM configuration

[source,bash]
----
docker compose up -d openam
----

Open http://openam.example.org:8080/openam[OpenAM] and configure the deployment. Set the session cookie domain to `.example.org` so the browser also sends the cookie to `openig.example.org`. Create a REST STS instance named `jwt` in the root realm that transforms an `OPENAM` token into an `OPENIDCONNECT` token. Use the `iPlanetDirectoryPro` session cookie configured in the example route. Follow the xref:openam:how-to:how-to-add-authorization-and-protect-your-application-with-openam-and-openig-stack.adoc#how-to-add-authorization-and-protect-your-application-with-openam-and-openig-stack-openam-setup[OpenAM setup instructions] for the STS configuration.

[source,bash]
----
docker compose up -d
----

[[how-to-protect-websocket-connection-with-openam-and-openig-test-solution]]
=== Test the connection

. While signed out of OpenAM, open http://openig.example.org:8081/ui[the WebSocket client] and select *Connect*. The upgrade fails.
. In a second tab, sign into http://openam.example.org:8080/openam[OpenAM]. Return to the WebSocket client, select *Connect*, and select *Send message*. The log shows `Connected` and the echoed `Test message`.
. Sign out of OpenAM, wait at least 180 seconds from the last authorization check and select *Send message* again. When OpenAM rejects the session on reauthorization, OpenIG closes the connection.
