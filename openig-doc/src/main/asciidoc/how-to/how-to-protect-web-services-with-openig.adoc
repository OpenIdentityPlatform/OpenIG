[[how-to-protect-web-services-with-openig-introduction]]
=== Introduction

Securing web services is critical part of production environment to prevent compromising application from attacks. In microservice architecture, there is no need to implement security for each microservice. Each microservice should be responsible for its atomic functionality. To protect services you need to use an API Gateway application. Consider how to protect simple web service with Open Identity Gateway (OpenIG) in the following article.

Source code for this article is located here: https://github.com/maximthomas/openig-protect-ws/

[[how-to-protect-web-services-with-openig-sample-service]]
=== Sample Service

Consider service application with 2 endpoints http://localhost:8080/ - public http://localhost:8080/secure - private, so only authenticated users should have access to it. This service implemented with https://spring.io/projects/spring-boot[Spring Boot:]

[source,java]
----
package org.openidentityplatform.sampleservice;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import javax.servlet.http.HttpServletRequest;
import java.util.Collections;
import java.util.Map;

@SpringBootApplication
public class SampleServiceApplication {
    public static void main(String[] args) {
        SpringApplication.run(SampleServiceApplication.class, args);
    }

    @RestController
    public class IndexController {
        @RequestMapping("/")
        public Map<String, String> index() {
            return Collections.singletonMap("hello", "world");
        }

        @RequestMapping("/secure")
        public Map<String, String> secure(HttpServletRequest request) {
            return Collections.singletonMap("hello", request.getHeader("X-Auth-Username"));
        }
    }
}
----

=== OpenIG Setup

Create OpenIG configuration folder `openig-config`. In this folder create another folder `config` with configuration files. In `openig-config/config` folder create 2 files:

`admin.json`

[source,json]
----
{
  "prefix" : "openig",
  "mode": "PRODUCTION"
}
----

and `config.json`

[source,json]
----
{
  "heap": [
  ],
  "handler": {
    "type": "Chain",
    "config": {
      "filters": [

      ],
      "handler": {
        "type": "Router",
        "name": "_router"
      }
    }
  }
}
----

Save the following as `compose.yaml` and create the `openig-config/scripts/` directory. The image uses `/var/openig` as its base.

[source,yaml]
----
services:
  sample-service:
    image: maximthomas/sample-service:latest
  openig:
    image: openidentityplatform/openig:latest
    volumes:
      - ./openig-config/config:/var/openig/config:ro
      - ./openig-config/scripts:/var/openig/scripts:ro
    environment:
      CATALINA_OPTS: -Dendpoint.api=http://sample-service:8080
    ports:
      - "127.0.0.1:8080:8080"
----

[[how-to-protect-web-services-with-openig-proxy-requests-to-sample-service]]
==== Proxy Requests to Sample Service

The `endpoint.api` upstream URI in Compose contains no path. A trailing slash would make OpenIG replace `/secure` with `/` when dispatching the request.

Add folder `routes` to `openig-config/config/` and add file `10-api.json` - main route to this folder. `10-api.json` route makes OpenIG proxy requests to `sample-service`

`10-api.json`:

[source,json]
----
{
  "name": "sample-api",
  "condition": "${request.uri.path == '/' or request.uri.path == '/secure'}",
  "monitor": true,
  "timer": true,
  "handler": {
    "type": "Chain",
    "config": {
      "filters": [

      ],
      "handler": "EndpointHandler"
    }
  },
  "heap": [
    {
      "name": "EndpointHandler",
      "type": "DispatchHandler",
      "config": {
        "bindings": [
          {
            "handler": "ClientHandler",
            "baseURI": "${system['endpoint.api']}"
          }
        ]
      }
    }
  ]
}
----

Add default route, which returns 404 status to all other requests

`99-default.json`:

[source,json]
----
{
  "name": "99-default",
  "handler": {
    "type": "StaticResponseHandler",
    "config": {
      "status": 404,
      "reason": "Not Found",
      "headers": {
        "Content-Type": [ "application/json" ]
      },
      "entity": "{ \"error\": \"Something went wrong, please contact your system administrator.\"}"
    }
  },
  "audit": "/404"
}
----

[[how-to-protect-web-services-with-openig-securing-sample-service]]
=== Securing Sample Service

There are https://github.com/OWASP/CheatSheetSeries/blob/master/cheatsheets/REST_Security_Cheat_Sheet.md[OWASP recommendations] to secure REST services:

[[how-to-protect-web-services-with-openig-http-methods-restriction]]
==== HTTP Methods Restriction

We will restrict HTTP methods, leave only GET and POST methods allowed. To do that add `SwitchFilter` to `10-api.json`:

[source,json]
----
{
  "name": "sample-api",
  "condition": "${request.uri.path == '/' or request.uri.path == '/secure'}",
  "monitor": true,
  "timer": true,
  "handler": {
    "type": "Chain",
    "config": {
      "filters": [
        {
          "type": "SwitchFilter",
          "config": {
            "onRequest": [
              {
                "condition": "${request.method != 'POST' and request.method != 'GET'}",
                "handler": {
                  "type": "StaticResponseHandler",
                  "config": {
                    "status": 405,
                    "reason": "Method Not Allowed",
                    "headers": {
                      "Allow": ["GET, POST"],
                      "Content-Type": [
                        "application/json"
                      ]
                    },
                    "entity": "{ \"error\": \"Method not allowed\"}"
                  }
                }
              }
            ]
          }
        }
      ],

      "handler": "EndpointHandler"
    }
  },
  "heap": [
    {
      "name": "EndpointHandler",
      "type": "DispatchHandler",
      "config": {
        "bindings": [
          {
            "handler": "ClientHandler",
            "baseURI": "${system['endpoint.api']}"
          }
        ]
      }
    }
  ]
}
----

[[how-to-protect-web-services-with-openig-validate-content-type-request-header]]
==== Validate Content-Type Request Header

To require a JSON media type for POST requests, replace the method filter with the following `SwitchFilter`. A missing or unsupported `Content-Type` returns 415.

`10-api.json`:

[source,json]
----
{
  "type": "SwitchFilter",
  "config": {
    "onRequest": [
      {
        "condition": "${request.method != 'POST' and request.method != 'GET'}",
        "handler": {
          "type": "StaticResponseHandler",
          "config": {
            "status": 405,
            "reason": "Method Not Allowed",
            "headers": {
              "Allow": [
                "GET, POST"
              ],
              "Content-Type": [
                "application/json"
              ]
            },
            "entity": "{ \"error\": \"Method not allowed\"}"
          }
        }
      },
      {
        "condition": "${request.method == 'POST' and not matches(request.headers['Content-Type'][0], '(?i)^\\\\s*application/json\\\\s*(;.*)?$')}",
        "handler": {
          "type": "StaticResponseHandler",
          "config": {
            "status": 415,
            "reason": "Unsupported Media Type",
            "headers": {
              "Content-Type": [
                "application/json"
              ]
            },
            "entity": "{ \"error\": \"Unsupported Media Type\"}"
          }
        }
      }
    ]
  }
}
----

Then check request with `Content-Type: application/xml` header:

[[how-to-protect-web-services-with-openig-validate-accept-request-header-and-content-type-response-header]]
==== Validate Accept Request Header and Content-Type Response Header

Check whether the response media type is acceptable to the client. An absent `Accept` header allows any media type; lists, wildcards and quality values need more than an exact string comparison. The most specific matching range takes precedence, including a `q=0` exclusion.

Add this object after the existing `SwitchFilter` in the route's `filters` array in `10-api.json`.

[source,json]
----
{
  "type": "ScriptableFilter",
  "config": {
    "type": "application/x-groovy",
    "file": "accept.groovy"
  }
}
----

Create `openig-config/scripts/groovy/accept.groovy`. The script uses the Apache HTTP header parser and Guava media-type parser already available in OpenIG, including their handling of quoted parameters. It checks all `Accept` field values, ignores malformed ranges and leaves responses without a parseable `Content-Type` unchanged. It does not select or convert the upstream representation; if no matching range has a positive quality, it replaces the response with 406.

[[how-to-protect-web-services-with-openig-add-response-security-headers-x-frame-options-and-x-content-type-options]]
==== Add Response Security Headers X-Frame-Options and X-Content-Type-Options

OpenIG should return `X-Frame-Options: deny` and `X-Content-Type-Options: nosniff` headers to client to prevent XSS and drag'n drop clickjacking attacks in older browsers. To do that, add `HeaderFilter` to filter chain after `SwitchFilter`:

`10-api.json`:

[source,json]
----
       {
          "type": "HeaderFilter",
          "comment": "Add security headers to response",
          "config": {
            "messageType": "response",
            "add": {
              "X-Frame-Options": [ "deny" ],
              "X-Content-Type-Options": [ "nosniff" ]
            }
          }
        }
----

Check response headers:

[listing]
----

[[how-to-protect-web-services-with-openig-authentication-check]]
==== Authentication Check

Use a locally signed JWT to test access to `/secure`. Generate an RSA key pair with OpenSSL and place only the public key in the mounted OpenIG configuration directory.

[source,bash]
----
mkdir -p openig-config/config/keys
(umask 077 && openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out private_key.pem)
openssl pkey -in private_key.pem -pubout -out openig-config/config/keys/public_key.pem
----

Save link:{how-to-downloads}/mint-jwt.py[mint-jwt.py] next to the private key. Run it with Python 3 and OpenSSL installed. The script issues an RS256 token valid for five minutes. It sets `iss` to `sample-service`, `aud` to `sample-api`, `sub` and `name` to the supplied username and `role` to the supplied role. Run it again when a token expires.

[source,bash]
----
TOKEN=$(python3 mint-jwt.py private_key.pem alice manager)
----

[[how-to-protect-web-services-with-openig-jwt-validation]]
==== JWT Validation

Append this `SwitchFilter` to the main route's `filters` array. It places the JWT filter on the `/secure` path. Keep the request method and media type checks before this filter so they still apply to both application paths.

`10-api.json`:

[source,json]
----
{
  "type": "SwitchFilter",
  "config": {
    "onRequest": [
      {
        "condition": "${request.uri.path == '/secure'}",
        "handler": {
          "type": "Chain",
          "config": {
            "filters": [
              {
                "type": "ScriptableFilter",
                "config": {
                  "type": "application/x-groovy",
                  "file": "jwt.groovy",
                  "args": {
                    "iss": {
                      "sample-service": "${read('/var/openig/config/keys/public_key.pem')}"
                    },
                    "audience": "sample-api"
                  }
                }
              }
            ],
            "handler": "EndpointHandler"
          }
        }
      }
    ]
  }
}
----

Create `openig-config/scripts/groovy/jwt.groovy`. The filter verifies the signature, issuer, expiration, audience and subject, then replaces the incoming identity header. It also makes the verified subject and role available to later filters through request attributes.

`jwt.groovy`:

[source,Groovy]
----
import groovy.json.JsonOutput
import java.security.KeyFactory
import java.security.spec.X509EncodedKeySpec
import org.forgerock.http.protocol.Response
import org.forgerock.http.protocol.Status
import org.forgerock.json.jose.builders.JwtBuilderFactory
import org.forgerock.json.jose.jws.JwsAlgorithm
import org.forgerock.json.jose.jws.SignedJwt
import org.forgerock.json.jose.jws.SigningManager

def authorization = request.headers['Authorization']?.firstValue
if (!authorization?.startsWith('Bearer ')) {
    return getErrorResponse(Status.UNAUTHORIZED, 'Not Authenticated')
}

def claims
def name
def role
try {
    def jwt = new JwtBuilderFactory().reconstruct(authorization.substring(7), SignedJwt.class)
    claims = jwt.claimsSet
    if (jwt.header.algorithm != JwsAlgorithm.RS256 ||
            !jwt.verify(new SigningManager().newRsaSigningHandler(getKey(claims)))) {
        return getErrorResponse(Status.UNAUTHORIZED, 'Not Authenticated')
    }
    def now = new Date()
    if (!claims.expirationTime?.after(now) || claims.notBeforeTime?.after(now) ||
            !claims.audience?.contains(audience) || !claims.subject) {
        return getErrorResponse(Status.UNAUTHORIZED, 'Not Authenticated')
    }
    name = claims.getClaim('name', String.class)
    role = claims.getClaim('role', String.class)
} catch (Exception ignored) {
    return getErrorResponse(Status.UNAUTHORIZED, 'Not Authenticated')
}
if (!name) {
    return getErrorResponse(Status.UNAUTHORIZED, 'Not Authenticated')
}
if (binding.hasVariable('allowedRoles') && !allowedRoles.contains(role)) {
    return getErrorResponse(Status.FORBIDDEN, 'Forbidden')
}
attributes['sub'] = claims.subject
attributes['role'] = role
request.headers.put('X-Auth-Username', name)
return next.handle(context, request)

def getErrorResponse(status, message) {
    def response = new Response(status)
    response.headers['Content-Type'] = 'application/json'
    response.setEntity(JsonOutput.toJson([error: message]))
    return response
}

def getKey(claims) {
    String pem = iss[claims.issuer]
    if (!pem) {
        throw new IllegalArgumentException('Unknown issuer')
    }
    byte[] encoded = Base64.getMimeDecoder().decode(
            pem.replace('-----BEGIN PUBLIC KEY-----', '').replace('-----END PUBLIC KEY-----', ''))
    return KeyFactory.getInstance('RSA').generatePublic(new X509EncodedKeySpec(encoded))
}
----

Run the first command with a fresh token to receive `{"hello":"alice"}`. A request without a token returns 401.

[source,bash]
----
curl -i -H "Authorization: Bearer $TOKEN" http://localhost:8080/secure
curl -i http://localhost:8080/secure
----

[[how-to-protect-web-services-with-openig-authorization-check]]
==== Authorization Check

Set `allowedRoles` in the JWT filter arguments to enforce the `role` claim. A valid token whose role is absent from the list receives 403 Forbidden.

[source,json]
----
{
  "type": "ScriptableFilter",
  "config": {
    "type": "application/x-groovy",
    "file": "jwt.groovy",
    "args": {
      "iss": {
        "sample-service": "${read('/var/openig/config/keys/public_key.pem')}"
      },
      "audience": "sample-api",
      "allowedRoles": ["manager"]
    }
  }
}
----

After updating the route, these requests produce 200 and 403 respectively.

[source,bash]
----
TOKEN=$(python3 mint-jwt.py private_key.pem alice manager)
curl -i -H "Authorization: Bearer $TOKEN" http://localhost:8080/secure
TOKEN=$(python3 mint-jwt.py private_key.pem bob bad)
curl -i -H "Authorization: Bearer $TOKEN" http://localhost:8080/secure
----
