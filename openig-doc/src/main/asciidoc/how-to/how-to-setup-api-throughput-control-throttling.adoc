[[how-to-setup-api-throughput-control-throttling]]
== How to Set Up API Throughput Control (Throttling)
:imagesdir: ../

[[how-to-setup-api-throughput-control-throttling-introduction]]
=== Introduction

OpenIG can limit requests to an upstream API by client or by authenticated user. Rate counters are local to each filter instance in each OpenIG process. Replicas enforce their own limits, and restarting OpenIG or reloading the route resets its counters.

[[how-to-setup-api-throughput-control-throttling-demo-project]]
=== Demo Project

Set up the xref:how-to-protect-web-services-with-openig.adoc[web service demo] through its authorization step. Keep the local RSA private key and `mint-jwt.py` in the working directory. The public key remains at `openig-config/config/keys/public_key.pem`.

[[how-to-setup-api-throughput-control-throttling-brief-demo-project-description]]
==== Demo endpoints

The public route at `/` and the authenticated path at `/secure` are defined in `openig-config/config/routes/10-api.json`. The JWT script verifies the signature and stores the verified JWT `sub` and `role` in request attributes.

[[how-to-setup-api-throughput-control-throttling-request-throttling-setup]]
=== Request Throttling Setup

[[how-to-setup-api-throughput-control-throttling-basic-throttling]]
==== Basic Throttling

Add this filter to the outer `filters` array of `10-api.json`. All requests to `/` share the same quota of five requests per five seconds. The conditional wrapper leaves `/secure` available for its own authenticated quota.

[source,json]
----
{
  "type": "ConditionalFilter",
  "config": {
    "condition": "${request.uri.path == '/'}",
    "delegate": {
      "type": "ThrottlingFilter",
      "name": "public-throttling",
      "config": {
        "requestGroupingPolicy": "all",
        "rate": {
          "numberOfRequests": 5,
          "duration": "5 seconds"
        }
      }
    }
  }
}
----

[[how-to-setup-api-throughput-control-throttling-grouped-throttling]]
==== Grouped Throttling

For a quota per client IP address, change the delegate's `requestGroupingPolicy` to the following expression.

[source,javascript]
----
"requestGroupingPolicy": "${contexts.client.remoteAddress}"
----

This uses the address from the servlet client context. If traffic passes through a trusted reverse proxy, configure how the container learns the original address from that proxy. Use forwarding headers only when a trusted proxy removes any client-provided values and sets them itself.

Issue seven requests in quick succession after the route loads.

[source,bash]
----
for i in $(seq 7); do
  curl -sS -o /dev/null -w '%{http_code}\n' http://localhost:8080/
done
----

With the default bursty strategy and an empty counter, five requests within the quota succeed. Excess requests receive 429. `Retry-After` gives the number of seconds to wait before retrying. The response also identifies the partition, rate and filter in `Retry-After-Partition`, `Retry-After-Rate`, and `Retry-After-Rule`.

[[how-to-setup-api-throughput-control-throttling-mapped-throttling-configuration]]
==== Mapped Throttling Configuration

Change the JWT filter's `allowedRoles` to `["manager", "supervisor"]`. In the nested chain for `/secure`, add the following filter immediately after the JWT filter. It groups requests by the verified subject. This example has one issuer, `sample-service`. For multiple issuers, combine the verified issuer and subject to keep identities from different issuers distinct.

[source,json]
----
{
  "type": "ThrottlingFilter",
  "name": "authenticated-throttling",
  "config": {
    "requestGroupingPolicy": "${attributes['sub']}",
    "throttlingRatePolicy": {
      "type": "MappedThrottlingPolicy",
      "config": {
        "throttlingRateMapper": "${attributes['role']}",
        "throttlingRatesMapping": {
          "supervisor": {
            "numberOfRequests": 10,
            "duration": "10 seconds"
          }
        },
        "defaultRate": {
          "numberOfRequests": 5,
          "duration": "10 seconds"
        }
      }
    }
  }
}
----

Issue fresh tokens for two distinct subjects. The manager gets five requests per ten seconds. The supervisor gets ten per ten seconds.

[source,bash]
----
MANAGER_TOKEN=$(python3 mint-jwt.py private_key.pem alice manager)
SUPERVISOR_TOKEN=$(python3 mint-jwt.py private_key.pem bob supervisor)

for i in $(seq 7); do
  curl -sS -o /dev/null -w '%{http_code}\n' \
    -H "Authorization: Bearer $MANAGER_TOKEN" http://localhost:8080/secure
done

for i in $(seq 12); do
  curl -sS -o /dev/null -w '%{http_code}\n' \
    -H "Authorization: Bearer $SUPERVISOR_TOKEN" http://localhost:8080/secure
done
----

With empty counters, each loop returns five or ten successful responses respectively before excess requests receive 429. Generate new tokens if the five-minute lifetime has elapsed.
