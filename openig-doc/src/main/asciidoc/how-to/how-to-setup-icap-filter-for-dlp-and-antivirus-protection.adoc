== How to Set Up an ICAP Filter for DLP and Antivirus Protection
:imagesdir: ../

[[how-to-setup-icap-filter-for-dlp-and-antivirus-protection-introduction]]
=== Introduction

The OpenIG `ICAP` filter sends request bodies to a content scanner using the https://www.rfc-editor.org/rfc/rfc3507.html[Internet Content Adaptation Protocol]. This example uses the scanner's REQMOD service to check uploads. Run it on loopback with sample data.

[[how-to-setup-icap-filter-for-dlp-and-antivirus-protection-setup-filter]]
=== Set Up the Filter

Start with the OpenIG installation in xref:gateway-guide:chap-quickstart.adoc#chap-quickstart[Getting Started]. Save this route as `config/routes/10-icap.json` under your OpenIG base directory, `$HOME/.openig` by default on Unix. The static response stands in for an upstream application. Its `X-Demo-Backend` header shows when the request reached that part of the chain.

[source,json]
----
{
  "name": "scan-upload",
  "condition": "${request.uri.path == '/scan' and (request.method == 'POST' or request.method == 'PUT')}",
  "handler": {
    "type": "Chain",
    "config": {
      "filters": [
        {
          "type": "ICAP",
          "config": {
            "server": "icap://127.0.0.1:1344",
            "service": "srv_clamav",
            "rewrite": "true",
            "connect_timeout": "5000",
            "read_timeout": "15000"
          }
        }
      ],
      "handler": {
        "type": "StaticResponseHandler",
        "config": {
          "status": 200,
          "headers": {"X-Demo-Backend": ["reached"]},
          "entity": "Reached the demo backend"
        }
      }
    }
  }
}
----

If OpenIG runs in Docker, put the scanner on the same private network and set `server` to the scanner service's URI, for example `icap://scanner:1344`. Then use the configured OpenIG host port for the checks below.

[cols="1,3"]
|===
|Scanner outcome |OpenIG behavior

|ICAP `204`
|Continues to the downstream handler.

|ICAP `200` with an encapsulated denial and `rewrite: "true"`
|Returns the scanner's HTTP response to the client.

|ICAP `200` and `rewrite: "false"`
|Continues to the downstream handler with the scanner's result headers on the request. Configure the downstream handler to enforce the result if this mode is used for protection.

|Scanner unreachable, times out, or returns an unexpected ICAP status
|Logs the problem and continues to the downstream handler, including when `rewrite` is `"true"`. Use a separate control if your deployment must reject uploads whenever scanning is unavailable.

|Request body cannot be read
|Versions with the unreadable-body handling return `400` before calling the scanner or downstream handler. Earlier releases can behave differently.
|===

Connection and read timeouts are expressed in milliseconds as strings or expressions that evaluate to strings. The filter skips empty bodies. See xref:reference:filters-conf.adoc#ICAP[ICAP] for the configuration fields.

[[how-to-setup-icap-filter-for-dlp-and-antivirus-protection-testing-solution]]
=== Test the Route

[[how-to-setup-icap-filter-for-dlp-and-antivirus-protection-setup-test-icap-server]]
==== Start the Scanner

Start the example scanner and wait for its antivirus engine to initialize. Check its logs for readiness. For production, use a maintained scanner and keep its signatures current.

[source,bash]
----
docker run -d --rm --name openig-icap-demo -p 127.0.0.1:1344:1344 \
  toolarium/toolarium-icap-calmav-docker:0.0.1
docker logs openig-icap-demo
----

Send a clean upload. Expect `200` and `X-Demo-Backend: reached`.

[source,bash]
----
printf 'OpenIG clean test\n' > clean.txt
curl -sS -i -X PUT --data-binary @clean.txt http://127.0.0.1:8080/scan
----

[[how-to-setup-icap-filter-for-dlp-and-antivirus-protection-getting-test-malicious-file]]
==== Get the EICAR Test File

Download `eicar.com.txt` from the https://www.eicar.org/download-anti-malware-testfile/[EICAR anti-malware test file page] to the current directory. It is a standard harmless scanner test fixture. Your workstation antivirus may intercept it.

[[how-to-setup-icap-filter-for-dlp-and-antivirus-protection-deny-content-mode--dicaprewritetrue]]
==== Test Deny Mode

With `rewrite` set to `"true"`, upload the test file. Expect the scanner's denial, typically `403` in this example. The response should omit `X-Demo-Backend`.

[source,bash]
----
curl -sS -i -X PUT --data-binary @eicar.com.txt http://127.0.0.1:8080/scan
----

[[how-to-setup-icap-filter-for-dlp-and-antivirus-protection-deny-content-notification-mode--dicaprewritefalse]]
==== Test Notification Mode

Set `rewrite` to `"false"`, wait for the route to reload, and repeat the test upload. Expect `200` and `X-Demo-Backend: reached`. The scanner result headers are supplied to the downstream request. A backend that uses these headers should accept them only from the trusted gateway and ensure that client-supplied values cannot be mistaken for scanner results.

[[how-to-setup-icap-filter-for-dlp-and-antivirus-protection-icap-denial-of-service-in--dicaprewritetrue-mode]]
==== Check Scanner Unavailability

Restore `rewrite` to `"true"` and wait for the route to reload. Stop the lab scanner, then repeat the clean upload. Verify both the scanner connection error in the gateway log and the `X-Demo-Backend: reached` header on the response. This distinguishes scanner unavailability from an explicit denial.

[source,bash]
----
docker stop openig-icap-demo
curl -sS -i -X PUT --data-binary @clean.txt http://127.0.0.1:8080/scan
----
