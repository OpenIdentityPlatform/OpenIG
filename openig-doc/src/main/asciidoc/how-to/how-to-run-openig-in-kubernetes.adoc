[[how-to-run-openig-in-kubernetes]]
== How to Run OpenIG in Kubernetes
:imagesdir: ../
include::../partials/how-to-downloads.adoc[]

[[how-to-run-openig-in-kubernetes-preface]]
=== Prerequisites

This example deploys OpenIG on Kubernetes and proxies `/info.0.json` to the xkcd API. It works with a local cluster and `kubectl`. For example, start Minikube as follows.

[source,bash]
----
minikube start --cpus=4 --memory=8g
----

For access through a Gateway, install a https://gateway-api.sigs.k8s.io/implementations/[Gateway API implementation] supported by your cluster. Use the local port-forward test to verify OpenIG without a Gateway.

[[how-to-run-openig-in-kubernetes-create-openig-service]]
=== OpenIG Service

Save link:{how-to-downloads}/kubernetes/openig.yaml[openig.yaml]. It defines a ClusterIP Service on port 8080 and a Deployment that reads OpenIG configuration from ConfigMaps. The pod runs as UID 1001, the non-root user in the OpenIG image.

[[how-to-run-openig-in-kubernetes-create-openig-configmaps]]
=== Create OpenIG ConfigMaps

[[how-to-run-openig-in-kubernetes-create-main-configmap]]
==== Main configuration

Create `config/admin.json` and `config/config.json`.

.config/admin.json
[source#kubernetes-admin-json,json]
----
{
  "prefix": "openig",
  "mode": "PRODUCTION"
}
----

.config/config.json
[source#kubernetes-config-json,json]
----
{
  "handler": {
    "type": "Router",
    "name": "_router"
  }
}
----

[source,bash]
----
kubectl create configmap openig-config --from-file=config/admin.json --from-file=config/config.json
----

[[how-to-run-openig-in-kubernetes-create-configmaps-for-openig-routes]]
==== Routes

Create these files in the `routes/` directory. The readiness probe uses `/healthz`, which is independent of the upstream and request method checks.

.routes/00-health.json
[source#kubernetes-health-route,json]
----
{
  "name": "health",
  "condition": "${request.uri.path == '/healthz'}",
  "handler": {
    "type": "StaticResponseHandler",
    "config": {
      "status": 200,
      "entity": "Ready"
    }
  }
}
----

.routes/10-api.json
[source#kubernetes-xkcd-route,json]
----
{
  "name": "xkcd-api",
  "condition": "${request.uri.path == '/info.0.json'}",
  "handler": {
    "type": "Chain",
    "config": {
      "filters": [
        {
          "type": "SwitchFilter",
          "config": {
            "onRequest": [
              {
                "condition": "${request.method != 'GET'}",
                "handler": {
                  "type": "StaticResponseHandler",
                  "config": {
                    "status": 405,
                    "headers": {
                      "Content-Type": [
                        "application/json"
                      ],
                      "Allow": [
                        "GET"
                      ]
                    },
                    "entity": "{\"error\":\"Method Not Allowed\"}"
                  }
                }
              }
            ]
          }
        },
        {
          "type": "HeaderFilter",
          "config": {
            "messageType": "REQUEST",
            "remove": [
              "Host"
            ]
          }
        }
      ],
      "handler": {
        "type": "DispatchHandler",
        "config": {
          "bindings": [
            {
              "handler": "ClientHandler",
              "baseURI": "https://xkcd.com"
            }
          ]
        }
      }
    }
  }
}
----

[source,bash]
----
kubectl create configmap openig-routes --from-file=routes/
----

[[how-to-run-openig-in-kubernetes-create-openig-deployment]]
=== Deploy OpenIG

[source,bash]
----
kubectl apply -f openig.yaml
kubectl rollout status deployment/openig
----

[[how-to-run-openig-in-kubernetes-check-if-openig-works]]
=== Test through the Service

Forward the OpenIG Service to local port 8080 in a separate terminal.

[source,bash]
----
kubectl port-forward service/openig 8080:8080
----

[source,bash]
----
curl -i http://localhost:8080/info.0.json
curl -i -X POST http://localhost:8080/info.0.json
----

The first request returns the xkcd JSON. OpenIG removes the incoming `Host` header so the HTTP client uses the upstream host. The second request returns 405 with `Allow: GET`.

[[how-to-run-openig-in-kubernetes-expose-openig-service-via-ingress]]
=== Expose the route with Gateway API

Create a `Gateway` named `demo` with an HTTP listener on port 80 in the same namespace as the OpenIG Service. Use the GatewayClass provided by your implementation. See the https://gateway-api.sigs.k8s.io/guides/getting-started/simple-gateway/[Gateway setup example].

Save the HTTPRoute below as `openig-route.yaml` and apply it. The exact match exposes just the demo API path and forwards it to OpenIG unchanged.

[source#kubernetes-xkcd-httproute,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: openig
spec:
  parentRefs:
    - name: demo
  rules:
    - matches:
        - path:
            type: Exact
            value: /info.0.json
      backendRefs:
        - name: openig
          port: 8080
----

[source,bash]
----
kubectl apply -f openig-route.yaml
kubectl describe httproute openig
kubectl get gateway demo
----

[[how-to-run-openig-in-kubernetes-test-access]]
==== Test through the Gateway

Check for `Accepted=True` and `ResolvedRefs=True` in the HTTPRoute status. When the Gateway is programmed, replace `GATEWAY_ADDRESS` with its reachable IP address or hostname.

[source,bash]
----
curl -i "http://GATEWAY_ADDRESS/info.0.json"
----
