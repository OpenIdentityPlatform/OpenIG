== REST API Security with OAuth 2.0, OpenAPI Validation and Monitoring
:imagesdir: ../
include::../partials/openig-release-version.adoc[]

[[rest-api-security-oauth-oidc-openapi-and-monitoring-what-this-article-is-about]]
=== What This Article Is About

Use OpenIG to authorize requests to Spring Pet Clinic with an OpenAM access token, validate requests and responses against OpenAPI, apply a per-user rate limit, and monitor the route.
You need Docker Compose, `curl`, `jq`, OpenSSL, Python 3, and a browser. Use the top-level OpenAM realm and an active, non-administrator test account for the OAuth flow.

[[rest-api-security-oauth-oidc-openapi-and-monitoring-what-threats-does-this-solution-address]]
=== What Does Validation Cover?

OpenIG validates only the rules expressed in the OpenAPI document. For example, to reject undeclared object properties, the corresponding schema must forbid them.
Keep application authorization in the backend and restrict direct network access to it. The lab uses HTTP on the local machine and the private Compose network. Use HTTPS for client requests and communication with OpenAM in a deployment.

[[rest-api-security-oauth-oidc-openapi-and-monitoring-preparation]]
=== Preparation

Start Pet Clinic with a temporary loopback port so you can download its OpenAPI specification. Create `docker-compose.yml`:

[source,yaml]
----
services:
  petclinic:
    image: springcommunity/spring-petclinic-rest:4.0.2
    ports:
      - "127.0.0.1:9966:9966"
----

[source,bash]
----
docker compose up -d petclinic
curl -fsS --retry 20 --retry-connrefused --retry-delay 1 \
  http://127.0.0.1:9966/petclinic/actuator/health
mkdir -p openig/config/openapi openig/config/routes
curl -fsS http://127.0.0.1:9966/petclinic/v3/api-docs.yaml \
  -H 'Host: petclinic:9966' -o petclinic.raw.yaml &&
  sed '/^    extensions: {}$/d' petclinic.raw.yaml > openig/config/openapi/petclinic.yaml
----

Wait for the health endpoint to return `UP` before downloading the specification. The `sed` step removes the empty `info.license.extensions` entry emitted by Pet Clinic 4.0.2, which OpenIG's OpenAPI parser rejects. Keep the OpenAPI file outside `config/routes` to prevent automatic creation of a second route for the same endpoint.

[[rest-api-security-oauth-oidc-openapi-and-monitoring-configuring-openig]]
=== Configuring OpenIG

Replace `docker-compose.yml` with the complete stack below. Pet Clinic has no host port after this change. The `openam.example.org` network alias is for container-to-container traffic. Add `127.0.0.1 openam.example.org` to your workstation's hosts file so the browser and CLI can reach OpenAM too.

[source,yaml,subs="verbatim,attributes"]
----
services:
  petclinic:
    image: springcommunity/spring-petclinic-rest:4.0.2
  openig:
    image: openidentityplatform/openig:{openig-version}
    ports:
      - "127.0.0.1:8081:8080"
    volumes:
      - ./openig/config:/var/openig/config:ro
    environment:
      CATALINA_OPTS: -Dopenam=http://openam.example.org:8080/openam
  openam:
    image: openidentityplatform/openam:16.1.4
    hostname: openam.example.org
    ports:
      - "127.0.0.1:8080:8080"
    volumes:
      - openam-data:/usr/openam/config
    networks:
      default:
        aliases:
          - openam.example.org
volumes:
  openam-data:
----

Create `openig/config/admin.json`:

[source,json]
----
{
  "mode": "PRODUCTION"
}
----

Create `openig/config/config.json`:

[source,json]
----
{
  "handler": {
    "name": "_router",
    "type": "Router",
    "config": {
      "openApiValidation": {
        "enabled": false
      }
    }
  }
}
----

[[rest-api-security-oauth-oidc-openapi-and-monitoring-configuring-a-route-to-the-pet-clinic-service]]
==== Configuring a Route to the Pet Clinic Service

Save the following as `openig/config/routes/20-petclinic.json`. This route uses an explicit validator, which lets you configure authentication, validation, and monitoring together.

[source,json]
----
{
  "name": "petclinic",
  "condition": "${matches(request.uri.path, '^/petclinic/api(?:/|$)')}",
  "baseURI": "http://petclinic:9966",
  "monitor": true,
  "handler": {
    "type": "Chain",
    "config": {
      "filters": [
        {
          "type": "OAuth2ResourceServerFilter",
          "config": {
            "requireHttps": false,
            "scopes": ["uid"],
            "tokenInfoEndpoint": "${system['openam'].concat('/oauth2/tokeninfo')}"
          }
        },
        {
          "type": "OpenApiValidationFilter",
          "config": {
            "spec": "${read('/var/openig/config/openapi/petclinic.yaml')}",
            "failOnResponseViolation": false
          }
        },
        {
          "type": "HeaderFilter",
          "config": {
            "messageType": "REQUEST",
            "remove": ["Authorization"]
          }
        }
      ],
      "handler": "ClientHandler"
    }
  }
}
----

`requireHttps: false` allows the lab's loopback HTTP requests. Omit it for an HTTPS deployment, and change the token info URL to the HTTPS OpenAM endpoint. Pet Clinic receives the validated application request without the bearer token.

[[rest-api-security-oauth-oidc-openapi-and-monitoring-configuring-authentication]]
==== Configuring Authentication

Start the stack with `docker compose up -d`. Open link:http://openam.example.org:8080/openam/[OpenAM] and complete the initial configuration with the embedded data store if this is a new installation. Set a password for the administrator and create or enable an active test user in the top-level realm.

Under *Realms > Top Level Realm*, choose *Configure OAuth Provider* and then *Configure OAuth 2.0*. Open the created OAuth2 Provider service and add `uid` to the supported scopes. Register a confidential OAuth 2.0 client named `petstore-app` under *Applications > OAuth 2.0*. Set its client secret, authorize the `uid` scope, keep `code` in *Response Types*, set the token endpoint authentication method to `client_secret_basic`, and register `http://127.0.0.1:8089/callback` as the redirect URI.

Check that the gateway rejects a request with no token:

[source,bash]
----
API_URL=http://127.0.0.1:8081/petclinic/api
curl -sS -o /dev/null -w '%{http_code}\n' "$API_URL/pets"
----

Expect `401`. Start an Authorization Code flow with PKCE from the same terminal you will use to exchange the code:

[source,bash]
----
OPENAM_URL=http://openam.example.org:8080/openam
REDIRECT_URI=http://127.0.0.1:8089/callback
STATE=$(openssl rand -hex 32)
CODE_VERIFIER=$(openssl rand -hex 32)
CODE_CHALLENGE=$(printf '%s' "$CODE_VERIFIER" | openssl dgst -sha256 -binary \
  | openssl base64 -A | tr '+/' '-_' | tr -d '=')

python3 - "$OPENAM_URL" "$REDIRECT_URI" "$STATE" "$CODE_CHALLENGE" <<'PYTHON'
import sys
from urllib.parse import urlencode

base, redirect, state, challenge = sys.argv[1:]
params = {
    'response_type': 'code',
    'client_id': 'petstore-app',
    'redirect_uri': redirect,
    'scope': 'uid',
    'state': state,
    'code_challenge': challenge,
    'code_challenge_method': 'S256',
}
print(base + '/oauth2/authorize?' + urlencode(params))
PYTHON
----

Open the printed URL in a private browser window, sign in as the test user and approve the requested scope. For this manual lab, no service listens on the loopback callback port, so the browser may display a connection error after redirecting. Copy the full callback URL from the address bar. The following block verifies `state` and the redirect target before extracting the code. When prompted by `curl`, enter the client secret configured in OpenAM.

[source,bash]
----
unset ACCESS_TOKEN
printf 'Callback URL: '
read -r CALLBACK_URL
if CODE=$(python3 - "$CALLBACK_URL" "$REDIRECT_URI" "$STATE" <<'PYTHON'
import sys
from urllib.parse import parse_qs, urlsplit

actual, expected = map(urlsplit, sys.argv[1:3])
params = parse_qs(actual.query)
if (actual._replace(query='', fragment='') != expected or
        params.get('state') != [sys.argv[3]] or len(params.get('code', [])) != 1):
    sys.exit('OAuth callback, state, or code did not match')
print(params['code'][0])
PYTHON
); then
  TOKEN_RESPONSE=$(curl -fsS --user petstore-app \
    --data-urlencode 'grant_type=authorization_code' \
    --data-urlencode "code=$CODE" \
    --data-urlencode "redirect_uri=$REDIRECT_URI" \
    --data-urlencode "code_verifier=$CODE_VERIFIER" \
    "$OPENAM_URL/oauth2/access_token") &&
  ACCESS_TOKEN=$(printf '%s' "$TOKEN_RESPONSE" | jq -er '.access_token')
fi
----

Use the fresh token to test access. Expect `200` and the JSON array of pets. Repeat the authorization flow when the token expires.

[source,bash]
----
curl -fsS -H "Authorization: Bearer $ACCESS_TOKEN" "$API_URL/pets" | jq .
----

For details of the OpenAM client settings and PKCE, see xref:openam:admin-guide:chap-oauth2.adoc[Managing OAuth 2.0 Authorization].

[[rest-api-security-oauth-oidc-openapi-and-monitoring-requests-and-responses-validation]]
==== Validating Requests and Responses

Send a pet update without its required `name`. Expect the validation filter to return `400` before contacting Pet Clinic. Check the OpenIG log for the schema violation.

[source,bash]
----
curl -sS -i -X PUT "$API_URL/owners/10/pets/12" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"birthDate":"2010-06-24","type":{"id":2,"name":"dog"}}'
docker compose logs openig
----

With `failOnResponseViolation: false`, the gateway logs invalid responses and passes them to the client. After correcting disagreements between Pet Clinic and the specification, set the flag to `true` and reload the route. The default handler then returns `503` for an invalid upstream response.

[[rest-api-security-oauth-oidc-openapi-and-monitoring-adding-api-throttling]]
==== Adding API Throttling

Insert the following object in the route's `filters` array immediately after `OAuth2ResourceServerFilter`, separating the objects with commas. The grouping key is the UID supplied by OpenAM's validated token information. Confirm that your provider returns a stable, nonempty value for each user before applying a per-user quota.

[source,json]
----
{
  "type": "ThrottlingFilter",
  "config": {
    "requestGroupingPolicy": "${contexts.oauth2.accessToken.info.uid}",
    "rate": {
      "numberOfRequests": 5,
      "duration": "5 seconds"
    }
  }
}
----

Wait for the route to reload. Send a burst with the same token. The token bucket starts with up to five requests and replenishes at an average rate of one request per second. A burst faster than that rate eventually receives `429`. Each OpenIG process has its own bucket.

[source,bash]
----
for request in $(seq 1 12); do
  curl -sS -o /dev/null -w '%{http_code}\n' \
    -H "Authorization: Bearer $ACCESS_TOKEN" "$API_URL/pets" &
done
wait
----

See xref:how-to-setup-api-throughput-control-throttling.adoc[How to Set Up API Throughput Control] for more examples.

[[rest-api-security-oauth-oidc-openapi-and-monitoring-monitoring-the-route]]
==== Monitoring the Route

The route enables metrics with `"monitor": true`. After sending traffic, look in the OpenIG log for `Monitoring endpoint available at`. In `PRODUCTION`, query the endpoint from inside the OpenIG container so the request comes from its loopback address:

[source,bash]
----
docker compose exec -T openig curl -fsS \
  http://127.0.0.1:8080/openig/api/system/objects/_router/routes/20-petclinic/monitoring \
  | jq '{requests, responses}'
----

Use the endpoint path reported in the log if you change the Router name or route filename. The result contains counters such as `requests.total`, `responses.success`, and `responses.clientError`. The request and response counts grow as you send traffic. Metrics are in memory and reset when the route is reloaded or the gateway is restarted. For details, see xref:reference:handlers-conf.adoc#crest-monitoring[The REST API for Monitoring].

[[rest-api-security-oauth-oidc-openapi-and-monitoring-conclusion]]
=== Conclusion

Check for `401` without a token, `200` with a valid token, `400` for an invalid request, and `429` during a burst. Use the route metrics and logs to verify the gateway's decisions. Stop the lab with `docker compose down` when finished.
