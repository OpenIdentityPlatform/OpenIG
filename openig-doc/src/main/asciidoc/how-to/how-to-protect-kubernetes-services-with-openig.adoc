[[how-to-protect-kubernetes-services-with-openig-preface]]
=== Prerequisites

This example puts OpenIG in front of a sample Kubernetes Service and validates methods and media types. Follow the xref:how-to-run-openig-in-kubernetes.adoc#how-to-run-openig-in-kubernetes-preface[cluster prerequisites]. For an example that also authenticates users, see xref:how-to-protect-web-services-with-openig.adoc[How to protect web services with OpenIG].

Use a new namespace or remove the previous demo before deploying this example. Both examples use the same OpenIG resource names.

[[how-to-protect-kubernetes-services-with-openig-deploy-sample-service-for-test]]
=== Deploy the sample service

Save link:{how-to-downloads}/kubernetes/sample-service.yaml[sample-service.yaml] and deploy the sample application. Its Service is reachable inside the cluster.

[source,bash]
----
kubectl apply -f sample-service.yaml
kubectl rollout status deployment/sample-service
----

[[how-to-protect-kubernetes-services-with-openig-create-configmaps-for-openig-routes]]
===== Routes and Accept filter

Copy `00-health.json` from the xref:how-to-run-openig-in-kubernetes.adoc#how-to-run-openig-in-kubernetes-create-configmaps-for-openig-routes[deployment guide] to the `routes/` directory. Add this sample service route in the same directory.

.routes/10-api.json
[source#kubernetes-sample-route,json]
----
{
  "name": "sample-api",
  "condition": "${request.uri.path == '/' or request.uri.path == '/secure'}",
  "handler": {
    "type": "Chain",
    "config": {
      "filters": [
        {
          "type": "SwitchFilter",
          "config": {
            "onRequest": [
              {
                "condition": "${request.method != 'GET' and request.method != 'POST'}",
                "handler": {
                  "type": "StaticResponseHandler",
                  "config": {
                    "status": 405,
                    "headers": {
                      "Content-Type": [
                        "application/json"
                      ],
                      "Allow": [
                        "GET, POST"
                      ]
                    },
                    "entity": "{\"error\":\"Method Not Allowed\"}"
                  }
                }
              },
              {
                "condition": "${request.method == 'POST' and not matches(request.headers['Content-Type'][0], '(?i)^\\\\s*application/json\\\\s*(;.*)?$')}",
                "handler": {
                  "type": "StaticResponseHandler",
                  "config": {
                    "status": 415,
                    "headers": {
                      "Content-Type": [
                        "application/json"
                      ]
                    },
                    "entity": "{\"error\":\"Unsupported Media Type\"}"
                  }
                }
              }
            ]
          }
        },
        {
          "type": "ScriptableFilter",
          "config": {
            "type": "application/x-groovy",
            "file": "accept.groovy"
          }
        },
        {
          "type": "HeaderFilter",
          "config": {
            "messageType": "RESPONSE",
            "add": {
              "X-Frame-Options": [
                "DENY"
              ],
              "X-Content-Type-Options": [
                "nosniff"
              ]
            }
          }
        }
      ],
      "handler": {
        "type": "DispatchHandler",
        "config": {
          "bindings": [
            {
              "handler": "ClientHandler",
              "baseURI": "http://sample-service:8080"
            }
          ]
        }
      }
    }
  }
}
----

The route returns 405 for methods other than GET and POST and supplies the `Allow` header. A POST with a missing or unsupported `Content-Type` returns 415. For other requests, the Accept filter checks the upstream media type against the client's media ranges, wildcards and quality values.

Save link:{how-to-downloads}/accept.groovy[accept.groovy] next to the manifest. Mount it under `/var/openig/scripts/groovy` through the scripts ConfigMap.

[source,bash]
----
kubectl create configmap openig-routes --from-file=routes/
kubectl create configmap openig-scripts --from-file=accept.groovy
----

[[how-to-protect-kubernetes-services-with-openig-check-if-openig-works]]
=== Test through the Service

In a separate terminal, forward the OpenIG Service to local port 8080.

[source,bash]
----
kubectl port-forward service/openig 8080:8080
----

[source,bash]
----
curl -i http://localhost:8080/
curl -i -H 'Accept: application/xml' http://localhost:8080/
curl -i -X PUT http://localhost:8080/
curl -i -X POST http://localhost:8080/
----

The first request accepts any media type and returns JSON with status 200. The subsequent requests return 406, 405 and 415, respectively.

[[how-to-protect-kubernetes-services-with-openig-expose-openig-via-ingress-and-test]]
=== Expose the sample service with Gateway API

Use the xref:how-to-run-openig-in-kubernetes.adoc#how-to-run-openig-in-kubernetes-expose-openig-service-via-ingress[same Gateway setup] with this HTTPRoute saved as `openig-route.yaml`. The two exact matches retain their paths when OpenIG dispatches them to the sample service.

[source#kubernetes-sample-httproute,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: openig
spec:
  parentRefs:
    - name: demo
  rules:
    - matches:
        - path:
            type: Exact
            value: /
        - path:
            type: Exact
            value: /secure
      backendRefs:
        - name: openig
          port: 8080
----

[source,bash]
----
kubectl apply -f openig-route.yaml
kubectl describe httproute openig
kubectl get gateway demo
----

[[how-to-protect-kubernetes-services-with-openig-test-access]]
==== Test through the Gateway

The first request below returns `{"hello":"world"}`. The second reaches the distinct `/secure` endpoint and returns the backend's greeting with no username. The third receives 406 because the backend responds with JSON.

[source,bash]
----
curl -i "http://GATEWAY_ADDRESS/"
curl -i -H 'Accept: application/json' "http://GATEWAY_ADDRESS/secure"
curl -i -H 'Accept: application/xml' "http://GATEWAY_ADDRESS/secure"
----
