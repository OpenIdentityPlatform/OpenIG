== How to Integrate OpenIG and Message Brokers
:imagesdir: ../

[[how-to-integrate-openig-and-message-brokers-introduction]]
=== Introduction

Open Identity Platform implemented message broker integration in xref:ROOT:index.adoc[OpenIG] starting with 5.0.12 version. https://kafka.apache.org[Apache Kafka] and https://www.ibm.com/products/mq[IBM MQ] are supported.

The following article shows an example how to send and receive messages from and to message brokers using xref:ROOT:index.adoc[OpenIG]

The examples use `$OPENIG_BASE/config/config.json` for heap objects and `$OPENIG_BASE/config/routes/` for route files. The https://github.com/maximthomas/openig-mb-example[original sample project] contains older Compose examples.

[[how-to-integrate-openig-and-message-brokers-use-cases]]
=== Use Cases

[[how-to-integrate-openig-and-message-brokers-send-http-requests-to-apache-kafka]]
==== Send HTTP requests to Apache Kafka

Start OpenIG with a running Kafka broker and an HTTP service that accepts POST requests at `/kafka2http`. This example assumes OpenIG and the Kafka command-line tools can reach the broker at `localhost:9092` and the HTTP service runs at `http://localhost:8081`. Set the following JVM options on OpenIG.

[source,text]
----
-Dkafka.bootstrap=localhost:9092
-Dendpoint.api=http://localhost:8081
----

For containers or remote brokers, use addresses reachable from OpenIG and make sure Kafka advertises addresses reachable from each client. Give `endpoint.api` without a trailing slash to preserve the request path.

Create both demo topics before starting OpenIG.

[source,bash]
----
kafka-topics.sh --create --topic topic1 --bootstrap-server localhost:9092
kafka-topics.sh --create --topic topic2 --bootstrap-server localhost:9092
----

Save the following main configuration. The producer sends to `topic1`. The consumer subscribes to `topic2` and creates an internal `POST /kafka2http` request for each record.

.config/config.json
[source#kafka-config,json]
----
{
  "heap": [
    {
      "name": "kafka-producer",
      "type": "MQ_Kafka",
      "config": {
        "bootstrap.servers": "${system['kafka.bootstrap']}",
        "topic.produce": "topic1"
      }
    },
    {
      "name": "kafka-consumer",
      "type": "MQ_Kafka",
      "config": {
        "bootstrap.servers": "${system['kafka.bootstrap']}",
        "topic.consume": "topic2",
        "group.id": "openig-http-demo",
        "method": "POST",
        "uri": "/kafka2http"
      }
    }
  ],
  "handler": {
    "type": "Router",
    "name": "_router"
  }
}
----

.config/routes/10-http2kafka.json
[source#kafka-producer-route,json]
----
{
  "name": "http-to-kafka",
  "condition": "${request.method == 'PUT' and request.uri.path == '/http2kafka'}",
  "handler": "kafka-producer"
}
----

Start OpenIG after adding both routes in this guide. Then send a request and read the Kafka topic.

[source,bash]
----
curl -i -X PUT http://localhost:8080/http2kafka \
  -H 'Content-Type: application/json' --data '{"data":"test"}'
kafka-console-consumer.sh --topic topic1 --from-beginning --bootstrap-server localhost:9092
----

OpenIG responds with HTTP 202 after Kafka acknowledges the write according to the producer's acknowledgement settings. This status confirms publication to the broker. The response includes the correlation ID and Kafka metadata. The producer stores the first value of each request header with the record, so remove credentials and other unwanted headers before passing requests to `MQ_Kafka`.

[[how-to-integrate-openig-and-message-brokers-send-apache-kafka-messages-to-http-endpoint]]
==== Send Apache Kafka messages to an HTTP endpoint

Add this route alongside `10-http2kafka.json`. The consumer's configured `uri` and method match the route condition. By default, `uri` would be `/kafka-consumer`, the consumer object's name prefixed with a slash, and the method would be PUT.

.config/routes/20-kafka2http.json
[source#kafka-consumer-route,json]
----
{
  "name": "kafka-to-http",
  "condition": "${request.method == 'POST' and request.uri.path == '/kafka2http'}",
  "handler": {
    "type": "DispatchHandler",
    "config": {
      "bindings": [
        {
          "handler": "ClientHandler",
          "baseURI": "${system['endpoint.api']}"
        }
      ]
    }
  }
}
----

Once OpenIG is running, send a record to `topic2`.

[source,bash]
----
printf '%s\n' '{"data":"test"}' | \
  kafka-console-producer.sh --topic topic2 --bootstrap-server localhost:9092
----

Check the upstream service logs for `POST /kafka2http` with the test body and the `kafka-topic: topic2` header. OpenIG submits dispatches asynchronously. The default Kafka offset auto-commit is independent of the HTTP response, so the example offers no guarantee that a failed HTTP request will be retried or that records will arrive in order.

[[how-to-integrate-openig-and-message-brokers-embedded-apache-kafka]]
==== Embedded Apache Kafka

For a local demo, add this heap object before the producer and consumer in the previous `config.json`. Start OpenIG, create `topic1` and `topic2`, and run the same commands as above. The listener and advertised address both point to loopback, so the Kafka tools must run on the same host as OpenIG.

.Embedded broker heap object
[source#kafka-embedded-heap,json]
----
{
  "name": "embedded-kafka",
  "type": "EmbeddedKafka",
  "config": {
    "zookeper.port": "2181",
    "listeners": "PLAINTEXT://127.0.0.1:9092",
    "advertised.listeners": "PLAINTEXT://127.0.0.1:9092"
  }
}
----

The configuration keys `zookeper.port` and `zookeper.connect` use the spelling shown here. Set `zookeper.port` to start an embedded ZooKeeper, or provide `zookeper.connect` for an external ZooKeeper. The embedded broker uses a temporary data directory by default. Set `path` to persist the embedded ZooKeeper files and the default Kafka log directory across restarts.

[[how-to-integrate-openig-and-message-brokers-send-http-requests-to-ibm-mq]]
==== Send HTTP Requests to IBM MQ

The following setup allows to receive messages via HTTP protocol and send them to IBM MQ queue.

Add the following IBM MQ producer object to the `heap` array in your existing `config.json`.

`config.json`

[source,json]
----
{
  "heap": [
    {
      "name": "mq-producer",
      "type": "MQ_IBM",
      "config": {
        "XMSC_WMQ_CONNECTION_NAME_LIST":"mq(1414)",
        "XMSC_WMQ_CHANNEL":"DEV.APP.SVRCONN",
        "XMSC_WMQ_QUEUE_MANAGER":"QM1",
        "XMSC_USERID":"app",
        "XMSC_PASSWORD":"passw0rd",
        "topic.produce": "DEV.QUEUE.1"
      }
    }
  ]
}
----

Some important *MQ++_++IBM* handler settings:

[cols=",",options="header",]
|===
|Setting |Name
|`XMSC++_++WMQ++_++CONNECTION++_++NAME++_++LIST` |Comma-separated list of host and port that are the addresses of the IBM MQ brokers
|`XMSC++_++WMQ++_++CHANNEL` |IBM MQ channel name, used for connection
|`XMSC++_++USERID` |IBM MQ user id
|`XMSC++_++PASSWORD` |IBM MQ user password
|`topic.produce` |Queue to which OpenIG sends messages
|`topic.consume` |Queue from which OpenIG consumes messages
|`uri` |OpenIG route endpoint
|`method` |HTTP method, which OpenIG uses to send requests to the HTTP endpoint
|===

Add OpenIG route to `routes` folder to process HTTP requests:

`10-http2mq.json`

[source,json]
----
{
  "name": "${(request.method == 'PUT') and matches(request.uri.path, '^/http2mq$')}",
  "condition": "${(request.method == 'PUT') and matches(request.uri.path, '^/http2mq$')}",
  "monitor": true,
  "timer": true,
  "handler": {
    "type": "Chain",
    "config": {
      "filters": [],
      "handler": {
        "type": "DispatchHandler",
        "config": {
          "bindings": [
            {
              "handler": "mq-producer"
            }
          ]
        }
      }
    }
  }
}
----

Send HTTP request to OpenIG and then check received messages in `DEV.QUEUE.1` topic

[source,bash]
----
$ curl -v -X PUT --data '{"data": "test"}' -H 'Content-Type: application/json' 'http://localhost:8080/http2mq'

[[how-to-integrate-openig-and-message-brokers-send-ibm-mq-messages-to-http-endpoint]]
==== Send IBM MQ Messages to HTTP Endpoint

Add the following IBM MQ consumer object to the `heap` array in your existing `config.json`.

`config.json`

[source,json]
----
{
  "heap": [
    {
      "name": "mq-consumer",
      "type": "MQ_IBM",
      "config": {
        "XMSC_WMQ_CONNECTION_NAME_LIST":"mq(1414)",
        "XMSC_WMQ_CHANNEL":"DEV.APP.SVRCONN",
        "XMSC_WMQ_QUEUE_MANAGER":"QM1",
        "XMSC_USERID":"app",
        "XMSC_PASSWORD":"passw0rd",
        "topic.consume": "DEV.QUEUE.2",
        "uri": "/mq2http",
        "method": "POST"
      }
    }
  ]
}
----

Add OpenIG route to `routes` folder to process IBM MQ messages:

`10-mq2http.json`

[source,json]
----
{
  "name": "${(request.method == 'POST') and matches(request.uri.path, '^/mq2http$')}",
  "condition": "${(request.method == 'POST') and matches(request.uri.path, '^/mq2http$')}",
  "monitor": true,
  "timer": true,
  "handler": {
    "type": "Chain",
    "config": {
      "filters": [],
      "handler": {
        "type": "DispatchHandler",
        "config": {
          "bindings": [
            {
              "handler": "ClientHandler",
              "capture": "all",
              "baseURI": "${system['endpoint.api']}"
            }
          ]
        }
      }
    }
  }
}

----

Log in to the IBM MQ console, and create a message for DEV.QUEUE.2 queue
